# desktop-composite-diff-review Specification

## Purpose
데스크톱 앱에서 현재 선택으로 통합 결과를 만들고, 변경 파일 목록과 읽기 전용
파일 검토 화면으로 확인하며, 진행 상태와 오류 복구 행동을 제공한다.
## Requirements
### Requirement: 현재 선택으로 통합 결과 생성
시스템은 사용자가 요청한 시점의 저장소, 비교 범위와 선택 커밋으로 통합 결과를 생성해야 한다(SHALL). 계산이 끝나기 전부터 진행 중 상태를 표시하고 중복 요청을 방지해야 한다(SHALL).

#### Scenario: 통합 결과 만들기
- **WHEN** 사용자가 하나 이상의 합성 가능 커밋을 선택하고 통합 결과 만들기를 실행한다
- **THEN** 시스템은 사용한 비교 기준, 작업 브랜치와 선택 커밋을 고정한다
- **AND** 즉시 계산 중 상태와 취소 컨트롤을 표시한다
- **AND** 같은 입력으로 중복 계산을 시작하는 컨트롤을 비활성화한다

#### Scenario: 결과 생성 후 선택 변경
- **WHEN** 완성된 통합 결과가 표시된 상태에서 사용자가 커밋 선택을 변경한다
- **THEN** 시스템은 이전 결과를 현재 선택의 결과로 표시하지 않는다
- **AND** 새 선택으로 통합 결과를 다시 만들어야 함을 안내한다

#### Scenario: 계산 중 선택 또는 범위 변경
- **WHEN** 통합 결과 계산 중 사용자가 커밋 선택이나 비교 범위를 변경한다
- **THEN** 시스템은 진행 중인 요청을 취소한다
- **AND** 이전 요청의 완료 값이 새 선택의 결과로 표시되지 않게 한다

### Requirement: 통합 결과 계산 취소
시스템은 사용자가 진행 중인 통합 결과 계산을 취소할 수 있게 해야 한다(SHALL). 취소된 계산의 결과는 완료 결과로 표시되지 않아야 한다(MUST NOT).

#### Scenario: 사용자가 계산 취소
- **WHEN** 사용자가 계산 중 표시된 취소 컨트롤을 실행한다
- **THEN** 시스템은 해당 계산을 중단하고 취소되었음을 표시한다
- **AND** 현재 커밋 선택을 유지해 다시 계산할 수 있게 한다

#### Scenario: 취소 응답보다 계산 완료가 늦게 도착
- **WHEN** 취소된 계산의 완료 응답이 이후에 도착한다
- **THEN** 시스템은 그 응답을 현재 결과와 변경 파일 목록에 반영하지 않는다

### Requirement: 통합 결과 범위 표시
시스템은 완성된 통합 결과에 실제 비교 기준 커밋, 포함된 커밋 수, 적용 순서와 작업 트리 보존 상태를 표시해야 한다(SHALL). 포함된 merge commit에는 계산에 사용한 기준 부모를 함께 표시해야 한다(SHALL). 그 기준 부모는 순서 번호가 아니라 병합받은 쪽인지 병합해 들여온 쪽인지로 표시해야 한다(MUST).

#### Scenario: 성공 결과 확인
- **WHEN** 선택 커밋의 통합 결과 생성이 성공한다
- **THEN** 시스템은 실제 비교 기준 커밋과 적용된 커밋을 오래된 순서부터 표시한다
- **AND** 화면의 선택 범위와 결과의 포함 범위가 일치함을 표시한다
- **AND** 현재 브랜치와 작업 중인 파일 상태가 변경되지 않았음을 표시한다

#### Scenario: 변경 파일이 없는 결과
- **WHEN** 선택 변경을 반영한 최종 상태가 비교 기준과 같아 변경 파일이 없다
- **THEN** 시스템은 계산이 성공했고 최종 변경 파일이 없음을 표시한다
- **AND** 이전 파일 선택과 diff를 제거한다

#### Scenario: merge commit이 포함된 결과 확인
- **WHEN** 기준 부모를 정한 merge commit이 포함된 통합 결과 생성이 성공한다
- **THEN** 시스템은 그 커밋에 사용한 기준 부모를 결과 범위와 함께 표시한다
- **AND** 병합받은 쪽인지 병합해 들여온 쪽인지로 표시한다
- **AND** 부모의 순서 번호로 표시하지 않는다

### Requirement: 변경 파일 목록 탐색
시스템은 성공한 통합 결과의 파일을 저장소 상대 경로 순서로 표시하고 추가, 수정과 삭제 상태를 구분해야 한다(SHALL). 문제 파일은 같은 목록의 원래 경로 위치에서 문제 상태로 구분해야 한다(MUST).

#### Scenario: 여러 변경 파일 확인
- **WHEN** 통합 결과에 추가, 수정 또는 삭제된 파일이 있다
- **THEN** 시스템은 각 파일의 저장소 상대 경로와 변경 상태를 안정적인 경로 순서로 표시한다
- **AND** 첫 번째 파일을 기본 탐색 대상으로 표시한다

#### Scenario: 키보드로 파일 변경
- **WHEN** 사용자가 키보드로 다른 변경 파일을 선택한다
- **THEN** 시스템은 파일 목록의 현재 위치와 선택 파일을 표시한다
- **AND** 파일 검토 화면을 선택한 파일 내용으로 갱신한다

#### Scenario: 문제 파일이 포함된 목록
- **WHEN** 통합 결과에 문제 파일이 있다
- **THEN** 시스템은 문제 파일을 경로 순서상 원래 위치에 표시한다
- **AND** 추가, 수정, 삭제와 구분되는 문제 상태로 표시한다
- **AND** 보조 기술에 그 파일이 문제 상태임을 알린다

### Requirement: 읽기 전용 파일 검토
시스템은 수정 또는 삭제된 텍스트 파일의 비교 기준 내용을 왼쪽에, 통합 결과
내용을 오른쪽에 두는 읽기 전용 좌우 diff를 제공해야 한다(SHALL). 추가된
텍스트 파일은 전체 내용을 한 번만 읽기 전용으로 표시해야 한다(SHALL). 통합 결과가
건드리지 않은 추적 파일은 비교 기준 내용을 하나의 문서로 표시해야 한다(MUST). 검토
화면은 지금 검토 중인 파일의 경로를 화면에 표시해야 한다(MUST).

#### Scenario: 수정 파일 비교
- **WHEN** 사용자가 수정 상태의 텍스트 파일을 선택한다
- **THEN** 시스템은 왼쪽에 비교 기준 파일, 오른쪽에 통합 결과 파일을 표시한다
- **AND** 파일 경로, 줄 번호와 대응하는 변경 구간을 함께 표시한다

#### Scenario: 검토 중인 파일 확인
- **WHEN** 사용자가 파일 검토 화면을 보고 있다
- **THEN** 시스템은 검토 중인 파일의 경로를 검토 화면 머리글에 표시한다
- **AND** 검토 대상이 바뀌면 표시된 경로도 함께 바뀐다

#### Scenario: 추가 파일 검토
- **WHEN** 사용자가 추가 상태의 텍스트 파일을 선택한다
- **THEN** 시스템은 기준 revision이 없음을 표시한다
- **AND** 기준 화면 없이 통합 결과 파일 전체 내용을 한 번 표시한다
- **AND** 표시된 모든 줄을 추가된 내용으로 구분한다

#### Scenario: 삭제 파일 비교
- **WHEN** 사용자가 삭제 상태의 텍스트 파일을 선택한다
- **THEN** 시스템은 왼쪽에 비교 기준 파일 내용을 표시한다
- **AND** 오른쪽을 빈 최종 상태로 표시한다

#### Scenario: 변경되지 않은 파일 검토
- **WHEN** 사용자가 통합 결과가 건드리지 않은 추적 파일을 선택한다
- **THEN** 시스템은 비교 기준 내용을 하나의 문서로 표시한다
- **AND** 그 내용이 선택 결과가 아님을 표시한다
- **AND** 좌우 비교 대상을 표시하지 않는다

#### Scenario: 파일 내용 편집 시도
- **WHEN** 사용자가 파일 검토 화면의 내용을 편집하려 한다
- **THEN** 시스템은 파일 내용을 변경하지 않고 읽기 전용 상태를 유지한다

#### Scenario: 보조 기술로 파일 검토 열기
- **WHEN** 사용자가 키보드 또는 보조 기술로 파일 검토 영역을 연다
- **THEN** 시스템은 파일 상태와 표시 중인 내용을 구분하는 이름 및 접근 가능한 변경 내용을 제공한다

### Requirement: 진단 및 재시도
시스템은 저장소 조회 또는 통합 결과 생성에 실패하면 문제 범위, 원인과 사용자가 수행할 다음 행동을 표시해야 한다(SHALL). 사용자가 입력을 고친 뒤 현재 화면에서 재시도할 수 있어야 한다(SHALL).

#### Scenario: 지원 범위를 벗어난 커밋
- **WHEN** 선택 커밋이 현재 비교 범위에 포함되지 않거나 적용 순서를 결정할 수 없다
- **THEN** 시스템은 문제가 된 커밋과 지원되지 않는 범위를 표시한다
- **AND** 비교 범위 또는 커밋 선택을 변경하는 행동을 안내한다

#### Scenario: 변경 적용 실패
- **WHEN** 선택한 변경을 통합하는 중 Git 오류가 발생한다
- **THEN** 시스템은 통합 결과를 완료 상태로 표시하지 않는다
- **AND** 실패한 작업 범위, 확인 가능한 원인과 저장소 상태를 확인한 뒤 재시도하는 행동을 안내한다
- **AND** 현재 저장소, 비교 범위와 커밋 선택을 유지한다

#### Scenario: 저장소 잠금, 접근 권한 또는 저장 장치 실패
- **WHEN** 통합 결과 생성이 저장소 잠금, 접근 권한 또는 저장 장치 문제로 실패한다
- **THEN** 시스템은 확인된 문제 범위를 구분해 표시한다
- **AND** 잠금을 해제하거나 접근 권한과 저장 공간을 확인한 뒤 다시 실행하는 행동을 안내한다
- **AND** Git 명령, 임시 경로와 원문 오류는 화면에 표시하지 않는다

#### Scenario: 화면 경계 호출 실패
- **WHEN** 데스크톱 화면과 로컬 작업 기능 사이의 요청이 잘못되거나 처리 중 연결이 끊긴다
- **THEN** 시스템은 현재 결과를 새 결과로 교체하지 않는다
- **AND** 요청한 작업, 실패 원인과 다시 실행할 행동을 표시한다

### Requirement: 최신 요청 결과 유지
시스템은 현재 저장소, 비교 범위와 선택 커밋이 모두 일치하는 가장 최근 요청의 결과만 화면에 표시해야 한다(MUST).

#### Scenario: 이전 요청이 나중에 완료됨
- **WHEN** 새 계산이 시작된 뒤 이전 계산이 더 늦게 완료된다
- **THEN** 시스템은 이전 계산 결과를 무시한다
- **AND** 새 계산의 진행 상태 또는 결과를 유지한다

#### Scenario: 다른 저장소를 연 뒤 이전 응답 도착
- **WHEN** 사용자가 다른 저장소를 연 뒤 이전 저장소의 조회 또는 계산 응답이 도착한다
- **THEN** 시스템은 이전 저장소의 커밋, 파일과 diff를 현재 화면에 표시하지 않는다

### Requirement: 사용자 Git 작업 상태 보존
시스템은 데스크톱 UI를 통한 조회와 통합 결과 계산의 성공, 실패 및 취소 후에도 사용자의 현재 브랜치, HEAD, staged 변경, unstaged 변경과 untracked 파일을 유지해야 한다(MUST).

#### Scenario: 작업 중인 저장소에서 결과 검토
- **WHEN** staged, unstaged와 untracked 파일이 있는 저장소에서 사용자가 통합 결과를 생성하고 파일 diff를 탐색한다
- **THEN** 현재 브랜치와 HEAD는 실행 전과 같다
- **AND** 작업 중인 모든 파일의 내용과 Git 상태도 실행 전과 같다

#### Scenario: 오류 또는 취소 후 상태 확인
- **WHEN** 통합 결과 생성이 실패하거나 사용자가 계산을 취소한다
- **THEN** 현재 브랜치, HEAD와 작업 중인 모든 파일 상태는 실행 전과 같다

### Requirement: 결과 상태 접근성
시스템은 계산 진행, 성공, 취소와 실패 상태를 화면 표시와 보조 기술 알림으로 제공해야 한다(SHALL). 상태를 전달하는 표시에는 색상 외의 이름 또는 모양이 포함되어야 한다(MUST).

#### Scenario: 계산 상태 변경 알림
- **WHEN** 통합 결과 상태가 대기, 계산 중, 성공, 취소 또는 실패로 변경된다
- **THEN** 시스템은 상태 이름과 필요한 행동을 화면에 표시한다
- **AND** 키보드 위치를 강제로 옮기지 않고 상태 변경을 보조 기술에 알린다

#### Scenario: 오류 후 키보드 이동
- **WHEN** 사용자가 오류 안내의 수정 또는 재시도 컨트롤을 실행한다
- **THEN** 시스템은 해당 문제를 해결하는 첫 번째 관련 컨트롤로 키보드 위치를 이동한다

### Requirement: 파일 검토 자원 정리
시스템은 diff 편집기 준비가 실패하거나 표시 대상이 바뀌면 해당 시도에서 만든
편집기, model과 장식을 모두 해제해야 한다(MUST).

#### Scenario: 편집기 model 연결 실패
- **WHEN** 파일 검토 편집기를 만든 뒤 model 연결 또는 장식 준비가 실패한다
- **THEN** 시스템은 해당 시도에서 만든 편집기와 model을 모두 해제한다
- **AND** 오류 경계에서 다시 시도할 수 있는 상태를 제공한다

#### Scenario: 파일 검토 대상 변경
- **WHEN** 사용자가 다른 파일을 선택하거나 파일 검토 화면을 닫는다
- **THEN** 시스템은 이전 파일에 사용한 편집기, model과 장식을 해제한다

### Requirement: 부분 결과 상태 표시
시스템은 문제 파일이 있는 결과를 완전한 결과와 구분해 표시해야 한다(MUST). 부분 결과에는 문제 파일 수와 해당 파일로 이동하는 수단을 제공해야 한다(MUST).

#### Scenario: 부분 결과 확인
- **WHEN** 문제 파일이 있는 통합 결과가 표시된다
- **THEN** 시스템은 결과가 실행 가능성이 검증되지 않은 부분 결과임을 표시한다
- **AND** 문제 파일 수를 함께 표시한다

#### Scenario: 문제 요약에서 문제 파일로 이동
- **WHEN** 사용자가 부분 결과의 문제 요약에서 이동 수단을 실행한다
- **THEN** 시스템은 첫 문제 파일을 선택 상태로 만든다
- **AND** 그 파일의 문제 내용을 검토 영역에 표시한다

#### Scenario: 완전한 결과 확인
- **WHEN** 문제 파일이 없는 통합 결과가 표시된다
- **THEN** 시스템은 부분 결과 표시와 문제 요약을 표시하지 않는다

### Requirement: 문제 파일 검토 화면
시스템은 문제 파일을 선택했을 때 완성된 diff 대신 문제 원인과 다음 행동을 표시해야 한다(MUST).

#### Scenario: 문제 파일 선택
- **WHEN** 사용자가 목록에서 문제 파일을 선택한다
- **THEN** 시스템은 좌우 diff를 표시하지 않는다
- **AND** 문제 원인, 관련 커밋과 사용자가 취할 다음 행동을 표시한다

#### Scenario: 문제 파일에서 정상 파일로 이동
- **WHEN** 사용자가 문제 파일을 본 뒤 정상 파일을 선택한다
- **THEN** 시스템은 그 파일의 좌우 diff를 표시한다

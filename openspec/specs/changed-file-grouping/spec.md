# changed-file-grouping Specification

## Purpose
사용자가 정의한 저장소 경로 prefix 규칙으로 `Changed Files`의 변경 파일을 그룹으로 묶어
본다. 규칙은 저장소별로 분리해 앱 설정에 보관하며, 검토 대상 저장소는 건드리지 않는다.

## Requirements

### Requirement: 그룹화 규칙 관리
시스템은 사용자가 경로 prefix와 그룹 이름을 짝지은 그룹화 규칙을 작성, 수정, 삭제할 수 있게 해야
한다(MUST). 규칙의 표시 순서를 사용자가 정할 수 있게 해야 한다(MUST). 규칙은 현재 열려 있는
저장소에만 적용해야 한다(MUST).

#### Scenario: 규칙 작성
- **WHEN** 사용자가 경로 prefix와 그룹 이름을 입력하고 규칙을 추가한다
- **THEN** 새 규칙이 규칙 목록의 마지막에 표시된다
- **AND** Config View에 해당 그룹이 나타난다

#### Scenario: 규칙 수정
- **WHEN** 사용자가 기존 규칙의 경로 prefix 또는 그룹 이름을 바꾼다
- **THEN** Config View의 그룹 이름과 그룹에 속한 파일이 바뀐 규칙에 맞게 갱신된다

#### Scenario: 규칙 삭제
- **WHEN** 사용자가 규칙을 삭제한다
- **THEN** 해당 그룹이 Config View에서 사라진다
- **AND** 그 그룹에 있던 파일이 다른 규칙에 걸리지 않으면 미분류 그룹에 표시된다

#### Scenario: 표시 순서 변경
- **WHEN** 사용자가 규칙의 순서를 바꾼다
- **THEN** Config View의 그룹이 바뀐 순서대로 표시된다
- **AND** 각 파일이 속한 그룹은 순서 변경으로 바뀌지 않는다

#### Scenario: 다른 저장소를 열었을 때
- **WHEN** 사용자가 규칙을 정의한 저장소를 닫고 다른 저장소를 연다
- **THEN** 앞 저장소의 규칙이 새 저장소의 Config View에 적용되지 않는다
- **AND** 새 저장소에 저장된 규칙이 있으면 그 규칙이 적용된다

### Requirement: 규칙에 따른 변경 파일 그룹화
시스템은 Config View에서 유효한 규칙마다 하나의 그룹을 표시해야 하며(MUST), 각 그룹에 그 규칙의
경로 prefix에 해당하는 변경 파일을 표시해야 한다(MUST). 경로 prefix는 저장소 상대 경로의 세그먼트
경계에서만 일치시켜야 한다(MUST). 그룹은 사용자가 정한 표시 순서대로 나타나야 한다(MUST).

#### Scenario: 규칙에 해당하는 파일 표시
- **WHEN** 사용자가 `tests/`를 경로 prefix로 하는 규칙을 정의하고 Config View를 연다
- **THEN** 해당 그룹에 `tests/` 아래의 변경 파일이 표시된다
- **AND** 각 파일의 저장소 상대 경로와 추가, 수정 또는 삭제 상태를 확인할 수 있다

#### Scenario: 세그먼트 경계가 아닌 일치
- **WHEN** 규칙의 경로 prefix가 `src/te`이고 변경 파일에 `src/test.txt`가 있다
- **THEN** `src/test.txt`는 해당 그룹에 표시되지 않는다

#### Scenario: 해당 파일이 없는 규칙
- **WHEN** 정의한 규칙의 경로 prefix에 해당하는 변경 파일이 없다
- **THEN** 그 그룹은 파일이 없는 그룹임을 알 수 있게 표시된다
- **AND** 사용자는 규칙이 적용되지 않은 것인지 해당 파일이 없는 것인지 구분할 수 있다

#### Scenario: 그룹 안 파일 선택
- **WHEN** 사용자가 그룹에 표시된 파일을 선택한다
- **THEN** diff 영역이 그 파일의 기준과 선택 결과를 표시한다
- **AND** 그 파일이 선택 상태로 표시된다

### Requirement: 겹치는 규칙의 우선순위
시스템은 한 파일 경로가 여러 규칙에 해당하면 가장 긴 경로 prefix를 가진 규칙을 적용해야 한다(MUST).
적용 결과는 규칙의 표시 순서와 무관해야 한다(MUST). 시스템은 각 파일에 적용된 규칙을 사용자가 확인할
수 있게 해야 한다(MUST).

#### Scenario: 상위 경로와 하위 경로가 모두 규칙일 때
- **WHEN** `src/`와 `src/test/`가 모두 규칙으로 정의되어 있고 변경 파일에 `src/test/a.java`가 있다
- **THEN** `src/test/a.java`는 `src/test/` 규칙의 그룹에 표시된다
- **AND** `src/` 규칙의 그룹에는 표시되지 않는다

#### Scenario: 표시 순서를 바꿔도 같은 결과
- **WHEN** 사용자가 겹치는 두 규칙의 표시 순서를 서로 바꾼다
- **THEN** 각 파일이 속한 그룹은 바뀌지 않는다
- **AND** 그룹이 화면에 나타나는 순서만 바뀐다

#### Scenario: 적용된 규칙 확인
- **WHEN** 사용자가 Config View에서 파일 하나의 적용 규칙을 확인한다
- **THEN** 그 파일에 적용된 경로 prefix와 그룹 이름을 확인할 수 있다

### Requirement: 미분류 파일 보존
시스템은 어떤 규칙에도 해당하지 않는 변경 파일을 별도의 미분류 그룹에 표시해야 한다(MUST). 미분류
그룹은 항상 마지막에 표시해야 하며(MUST), 사용자가 삭제하거나 순서를 바꿀 수 없어야 한다(MUST).
Config View에 표시된 파일 수의 합은 변경 파일 전체 수와 같아야 한다(MUST).

#### Scenario: 규칙에 걸리지 않은 파일
- **WHEN** 변경 파일 중 어떤 규칙의 경로 prefix에도 해당하지 않는 파일이 있다
- **THEN** 그 파일이 미분류 그룹에 표시된다
- **AND** 미분류 그룹이 그룹 목록의 마지막에 표시된다

#### Scenario: 전체 파일 수 보존
- **WHEN** 사용자가 Config View와 List View를 차례로 확인한다
- **THEN** Config View의 모든 그룹에 표시된 파일 수의 합이 List View의 파일 수와 같다
- **AND** 두 보기의 저장소 상대 경로 집합이 동일하다

#### Scenario: 미분류 파일이 없을 때
- **WHEN** 모든 변경 파일이 규칙에 해당한다
- **THEN** 미분류 그룹이 표시되지 않는다

#### Scenario: 문제 파일과 바이너리 파일
- **WHEN** 문제 파일 또는 바이너리 파일이 있는 결과에서 사용자가 Config View를 확인한다
- **THEN** 그 파일도 다른 파일과 같은 규칙으로 그룹에 표시된다
- **AND** 문제 상태가 다른 보기와 동일하게 표시된다

### Requirement: 잘못된 규칙 안내
시스템은 잘못된 규칙을 조용히 무시하지 않아야 하며(MUST NOT), 문제 범위와 원인, 사용자가 취할 수 있는
다음 행동을 표시해야 한다(MUST). 잘못된 규칙이 있어도 유효한 규칙으로 그룹화를 계속해야 한다(MUST).

#### Scenario: 빈 경로 prefix
- **WHEN** 사용자가 경로 prefix를 비운 채 규칙을 저장한다
- **THEN** 시스템은 그 규칙을 적용하지 않고 원인과 다음 행동을 표시한다
- **AND** 다른 규칙의 그룹은 그대로 표시된다

#### Scenario: 저장소 상대 경로가 아닌 prefix
- **WHEN** 사용자가 절대 경로나 `..`를 포함한 경로 prefix를 저장한다
- **THEN** 시스템은 저장소 상대 경로가 필요하다는 원인과 다음 행동을 표시한다
- **AND** 그 규칙은 적용되지 않는다

#### Scenario: 중복된 경로 prefix
- **WHEN** 사용자가 이미 있는 규칙과 같은 경로 prefix로 규칙을 추가한다
- **THEN** 시스템은 어떤 규칙과 중복되는지와 다음 행동을 표시한다
- **AND** 중복된 규칙은 추가되지 않는다

#### Scenario: 중복된 그룹 이름
- **WHEN** 사용자가 이미 있는 규칙과 같은 그룹 이름으로 규칙을 추가한다
- **THEN** 시스템은 어떤 규칙과 이름이 겹치는지와 다음 행동을 표시한다
- **AND** 중복된 규칙은 추가되지 않는다

#### Scenario: 규칙 수 상한 도달
- **WHEN** 저장된 규칙 수가 시스템 상한을 넘는다
- **THEN** 시스템은 상한까지의 규칙으로 그룹을 표시한다
- **AND** 상한에 도달했음과 다음 행동을 표시한다

### Requirement: 저장소별 규칙 보관과 복원
시스템은 사용자가 정의한 규칙을 저장소별로 분리해 보관해야 하며(MUST), 앱을 다시 실행한 뒤 같은
저장소를 열면 그 규칙을 복원해야 한다(MUST). 시스템은 규칙을 검토 대상 저장소의 작업 트리에
저장하지 않아야 한다(MUST NOT).

#### Scenario: 앱 재실행 후 복원
- **WHEN** 사용자가 규칙을 정의하고 앱을 종료한 뒤 다시 실행해 같은 저장소를 연다
- **THEN** 정의한 규칙과 표시 순서가 그대로 복원된다
- **AND** Config View가 같은 그룹을 표시한다

#### Scenario: 저장소 상태 보존
- **WHEN** 사용자가 규칙을 저장하고 Config View로 검토한다
- **THEN** 검토 전후로 사용자의 branch, HEAD와 작업 트리 상태가 동일하다
- **AND** 검토 대상 저장소에 새 파일이 생기지 않는다

#### Scenario: 규칙을 보관하지 못했을 때
- **WHEN** 규칙을 저장하는 데 실패한다
- **THEN** 시스템은 저장하지 못했다는 사실과 원인, 다음 행동을 표시한다
- **AND** 화면에서 편집 중이던 규칙 내용이 사라지지 않는다

#### Scenario: 보관된 규칙을 읽지 못했을 때
- **WHEN** 보관된 규칙을 읽을 수 없거나 내용을 해석할 수 없다
- **THEN** 시스템은 원인과 다음 행동을 표시하고 보관된 내용을 덮어쓰지 않는다
- **AND** Tree View와 List View는 평소대로 사용할 수 있다

### Requirement: 규칙이 없을 때의 안내
시스템은 규칙이 하나도 없어도 Config View를 선택할 수 있게 해야 하며(MUST), 규칙이 없다는 사실과
규칙을 만드는 방법을 표시해야 한다(MUST).

#### Scenario: 규칙 없이 Config View 선택
- **WHEN** 규칙이 하나도 없는 저장소에서 사용자가 Config View를 선택한다
- **THEN** 규칙이 없다는 안내와 규칙을 만드는 방법이 표시된다
- **AND** 사용자는 그 자리에서 규칙 편집을 시작할 수 있다

#### Scenario: 첫 규칙을 만든 직후
- **WHEN** 사용자가 안내에서 첫 규칙을 만든다
- **THEN** 안내가 사라지고 그 규칙의 그룹과 미분류 그룹이 표시된다

### Requirement: 그룹 접기와 펼치기
시스템은 Config View의 각 그룹을 접고 펼 수 있게 해야 하며(MUST), 현재 펼침 상태를 보조 기술에
제공해야 한다(MUST). 그룹을 접거나 펴도 선택 파일과 현재 diff는 바뀌지 않아야 한다(MUST NOT).

#### Scenario: 그룹 접기
- **WHEN** 사용자가 그룹 머리 행을 실행한다
- **THEN** 그 그룹에 속한 파일이 표시되지 않는다
- **AND** 그룹 머리 행이 접힌 상태로 표시된다

#### Scenario: 그룹 다시 펼치기
- **WHEN** 사용자가 접힌 그룹 머리 행을 다시 실행한다
- **THEN** 그 그룹의 파일이 다시 표시된다
- **AND** 선택 파일과 현재 diff는 변경되지 않는다

#### Scenario: 접힌 그룹의 파일 수
- **WHEN** 그룹이 접혀 있다
- **THEN** 사용자는 그 그룹에 속한 파일 수를 확인할 수 있다

### Requirement: 키보드로 그룹 탐색
시스템은 키보드만으로 Config View의 그룹을 이동하고 접고 펴며 파일을 선택할 수 있게 해야 한다(MUST).
각 그룹과 파일에 보이는 이름 또는 접근 가능한 이름을 제공해야 한다(MUST).

#### Scenario: 키보드로 그룹 이동과 펼침
- **WHEN** 사용자가 Tab으로 그룹 머리 행에 포커스하고 Space 또는 Enter를 누른다
- **THEN** 그 그룹이 접히거나 펼쳐진다
- **AND** 포커스 위치와 펼침 상태를 확인할 수 있다

#### Scenario: 키보드로 파일 선택
- **WHEN** 사용자가 키보드로 그룹 안의 파일에 포커스하고 실행한다
- **THEN** 그 파일이 선택되고 diff 영역이 그 파일을 표시한다

#### Scenario: 키보드로 규칙 편집 열기
- **WHEN** 사용자가 키보드로 규칙 편집 진입점에 포커스하고 실행한다
- **THEN** 규칙 편집을 시작할 수 있는 상태가 되고 포커스가 그 안으로 이동한다

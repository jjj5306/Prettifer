# diff-view-mode Specification

## Purpose
파일 검토 화면에서 기준과 결과를 좌우로 놓는 보기와 삭제·추가를 하나의 흐름으로 잇는
세로 보기를 전환한다. 전환은 보고 있던 위치와 선택 파일을 유지한다.

## Requirements

### Requirement: diff 보기 전환
시스템은 파일 검토 화면에서 좌우 보기와 세로 보기를 선택하는 토글을 제공해야 한다(MUST). 현재 선택된 보기를 시각 및 보조 기술 상태로 표시해야 한다(MUST). 기본 보기는 좌우여야 한다(MUST).

#### Scenario: 세로 보기 선택
- **WHEN** 사용자가 세로 보기 토글을 선택한다
- **THEN** 기준의 삭제된 줄과 결과의 추가된 줄이 하나의 흐름으로 이어져 표시된다
- **AND** 세로 보기 토글이 선택 상태로 표시된다

#### Scenario: 좌우 보기 선택
- **WHEN** 사용자가 세로 보기에서 좌우 보기 토글을 선택한다
- **THEN** 기준이 왼쪽, 선택 결과가 오른쪽에 표시된다
- **AND** 좌우 보기 토글이 선택 상태로 표시된다

#### Scenario: 처음 검토를 열었을 때
- **WHEN** 사용자가 파일을 처음 검토한다
- **THEN** 좌우 보기가 선택 상태로 표시된다

### Requirement: 보기 전환의 맥락 보존
시스템은 보기를 전환한 뒤 검토 중인 파일과 보고 있던 위치를 유지해야 한다(MUST). 보기 전환은 통합 결과를 다시 계산하거나 저장소를 다시 읽지 않아야 한다(MUST NOT).

#### Scenario: 보고 있던 위치 유지
- **WHEN** 사용자가 diff를 아래로 스크롤한 뒤 보기를 전환한다
- **THEN** 검토 화면은 전환 전과 같은 위치를 계속 보여 준다
- **AND** 검토 중인 파일은 그대로 유지된다

#### Scenario: 전환만 수행
- **WHEN** 사용자가 결과를 변경하지 않고 보기를 전환한다
- **THEN** 시스템은 새 결과 계산이나 저장소 요청을 시작하지 않는다

#### Scenario: 보기를 유지한 채 다른 파일 검토
- **WHEN** 사용자가 세로 보기에서 다른 변경 파일을 선택한다
- **THEN** 그 파일도 세로 보기로 표시된다

### Requirement: 비교 대상이 없는 화면의 보기 토글
시스템은 좌우로 비교할 기준이 없는 검토 화면에서는 보기 토글을 제공하지 않아야 한다(MUST NOT). 그런 화면의 표시는 보기 선택과 무관하게 같아야 한다(MUST).

#### Scenario: 추가된 파일
- **WHEN** 사용자가 추가된 파일을 검토한다
- **THEN** 보기 토글이 표시되지 않는다
- **AND** 파일 전체 내용이 추가된 내용으로 한 번 표시된다

#### Scenario: 선택 결과에 없는 파일
- **WHEN** 사용자가 선택 결과에 없는 파일을 검토한다
- **THEN** 보기 토글이 표시되지 않는다

#### Scenario: 비교할 텍스트가 없는 파일
- **WHEN** 사용자가 바이너리 파일이나 문제 파일을 검토한다
- **THEN** 보기 토글이 표시되지 않는다

### Requirement: 접근 가능한 보기 토글
시스템은 키보드로 보기를 선택할 수 있게 해야 하며(MUST), 각 토글에 보이는 이름 또는 접근 가능한 이름과 선택 상태를 제공해야 한다(MUST). 두 보기 모두 읽기 전용이어야 한다(MUST).

#### Scenario: 키보드로 보기 변경
- **WHEN** 사용자가 Tab으로 보기 토글에 포커스하고 Space 또는 Enter를 누른다
- **THEN** 포커스한 보기가 활성화된다
- **AND** 포커스 위치와 활성 보기를 확인할 수 있다

#### Scenario: 세로 보기에서 편집 시도
- **WHEN** 사용자가 세로 보기의 내용을 편집하려 한다
- **THEN** 시스템은 내용을 변경하지 않고 읽기 전용 상태를 유지한다

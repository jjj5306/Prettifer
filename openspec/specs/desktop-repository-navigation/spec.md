# desktop-repository-navigation Specification

## Purpose
Windows 데스크톱 앱에서 로컬 Git 저장소를 열고 비교 범위와 선형 커밋 흐름을
탐색하며, 합성 선택과 현재 탐색 상태를 구분해 다룰 수 있게 한다.

## Requirements

### Requirement: Windows 데스크톱 앱 실행
시스템은 설치된 Windows 패키지와 개발 실행 명령에서 하나의 Prettifer 데스크톱 창을 열어야 한다(SHALL).

#### Scenario: 패키지 앱 실행
- **WHEN** 사용자가 생성된 Windows 패키지의 Prettifer 실행 파일을 연다
- **THEN** 시스템은 저장소를 선택할 수 있는 단일 데스크톱 창을 표시한다
- **AND** 창을 닫으면 실행 중인 저장소 조회와 통합 결과 계산을 정리한 뒤 프로세스를 종료한다

### Requirement: 로컬 Git 저장소 열기
시스템은 운영체제 폴더 선택 창을 통해 로컬 Git 저장소를 열고 현재 열린 저장소를 명확히 표시해야 한다(SHALL).

#### Scenario: 유효한 저장소 선택
- **WHEN** 사용자가 폴더 선택 창에서 유효한 로컬 Git 저장소를 선택한다
- **THEN** 시스템은 저장소의 정규화된 경로와 현재 브랜치를 표시한다
- **AND** 비교 범위 선택 화면을 사용할 수 있게 한다

#### Scenario: 폴더 선택 취소
- **WHEN** 사용자가 폴더 선택 창을 취소한다
- **THEN** 시스템은 현재 열려 있는 저장소와 화면 상태를 유지한다

#### Scenario: Git 저장소가 아닌 폴더 선택
- **WHEN** 사용자가 Git 저장소가 아닌 폴더를 선택한다
- **THEN** 시스템은 문제가 발생한 경로와 저장소를 열 수 없는 원인을 표시한다
- **AND** 다른 폴더를 선택하는 행동을 안내한다
- **AND** 이전에 정상적으로 연 저장소가 있으면 그 상태를 유지한다

#### Scenario: Git 실행 파일을 사용할 수 없음
- **WHEN** 시스템이 로컬 Git 실행 파일을 찾거나 실행할 수 없다
- **THEN** 시스템은 Git 실행 환경이 필요함을 표시한다
- **AND** Git 설치와 실행 경로를 확인하는 행동을 안내한다

### Requirement: 비교 범위 선택
시스템은 열린 저장소의 로컬 브랜치를 제공하고, 사용자가 비교 기준 브랜치와 작업 브랜치를 독립적으로 선택하게 해야 한다(SHALL). 시스템은 실제 비교에 사용할 두 브랜치의 공통 조상을 표시해야 한다(SHALL).

#### Scenario: 비교 기준과 작업 브랜치 선택
- **WHEN** 사용자가 비교 기준 브랜치와 작업 브랜치를 선택한다
- **THEN** 시스템은 두 브랜치가 갈라진 공통 조상 커밋을 계산해 표시한다
- **AND** 해당 공통 조상부터 작업 브랜치까지의 지원되는 커밋 흐름을 불러온다

#### Scenario: 현재 브랜치 확인
- **WHEN** 열린 저장소의 로컬 브랜치 목록이 표시된다
- **THEN** 시스템은 현재 작업 중인 브랜치를 다른 브랜치와 구분해 표시한다

#### Scenario: 비교 범위를 만들 수 없음
- **WHEN** 선택한 브랜치가 존재하지 않거나 필요한 공통 이력이 없어 비교 범위를 만들 수 없다
- **THEN** 시스템은 확인할 수 없는 브랜치 또는 이력 범위와 원인을 표시한다
- **AND** 브랜치 선택을 변경하거나 필요한 이력을 준비하는 행동을 안내한다

#### Scenario: 비교 범위 변경
- **WHEN** 사용자가 비교 기준 브랜치 또는 작업 브랜치를 변경한다
- **THEN** 시스템은 이전 범위의 커밋 선택, 탐색 대상과 통합 결과를 제거한다
- **AND** 새 범위의 공통 조상과 커밋 흐름을 표시한다

### Requirement: 선형 커밋 흐름 탐색
시스템은 현재 지원 범위에 맞게 작업 브랜치의 첫 번째 부모를 따라가는 선형 커밋 흐름을 최신 커밋부터 표시해야 한다(SHALL).

#### Scenario: 커밋 정보 확인
- **WHEN** 선택한 비교 범위에 커밋이 있다
- **THEN** 시스템은 각 커밋의 짧은 ID, 제목, 작성자와 작성 시각을 최신순으로 표시한다
- **AND** 합성할 수 있는 커밋에 선택 컨트롤을 제공한다

#### Scenario: merge commit 확인
- **WHEN** 선형 흐름에 부모가 둘 이상인 merge commit이 포함된다
- **THEN** 시스템은 해당 커밋이 merge commit임을 표시한다
- **AND** 이번 지원 범위에서 선택할 수 없는 이유를 해당 행에서 안내한다

#### Scenario: 비교 범위에 커밋이 없음
- **WHEN** 공통 조상 이후 작업 브랜치에 표시할 커밋이 없다
- **THEN** 시스템은 현재 비교 범위에 선택할 커밋이 없음을 표시한다
- **AND** 다른 브랜치 범위를 선택하는 행동을 안내한다

#### Scenario: 이전 커밋 추가 로딩
- **WHEN** 현재 페이지보다 오래된 커밋이 있고 사용자가 이전 커밋을 더 불러온다
- **THEN** 시스템은 이미 표시된 커밋, 체크 상태와 현재 키보드 위치를 유지한 채 다음 커밋 페이지를 추가한다

#### Scenario: 조회 중 브랜치 이동
- **WHEN** 화면을 연 뒤 작업 브랜치가 다른 커밋을 가리키도록 변경된다
- **THEN** 시스템은 현재 목록이 최신 브랜치 상태와 다름을 표시한다
- **AND** 사용자가 새 이력을 불러오기 전에는 기존 커밋을 새 결과의 입력으로 사용하지 않는다

### Requirement: 합성 선택과 현재 탐색 구분
시스템은 통합 결과에 포함할 커밋의 체크 상태와 현재 자세히 살펴보는 커밋의 탐색 상태를 서로 다른 표시로 유지해야 한다(SHALL).

#### Scenario: 비연속 커밋 선택
- **WHEN** 사용자가 선형 흐름에서 서로 떨어진 합성 가능 커밋의 체크 상자를 선택한다
- **THEN** 시스템은 선택한 모든 커밋의 체크 상태와 선택 개수를 표시한다
- **AND** 사이에 있는 선택하지 않은 커밋은 체크되지 않은 상태로 유지한다

#### Scenario: 선택하지 않은 커밋 탐색
- **WHEN** 사용자가 합성 대상으로 체크하지 않은 커밋 행을 연다
- **THEN** 시스템은 기존 체크 상태를 유지한다
- **AND** 현재 살펴보는 커밋만 별도의 탐색 상태로 표시한다

#### Scenario: 모든 선택 해제
- **WHEN** 사용자가 모든 커밋의 체크를 해제한다
- **THEN** 시스템은 선택 개수를 0으로 표시한다
- **AND** 통합 결과를 만들려면 하나 이상의 커밋을 선택해야 함을 안내한다

### Requirement: 키보드 및 화면 확대 지원
시스템은 저장소 열기, 비교 범위 선택, 커밋 탐색과 합성 선택을 키보드로 수행할 수 있게 해야 한다(SHALL). 현재 키보드 위치와 합성 선택은 색상 외의 표시로도 구분되어야 한다(MUST).

#### Scenario: 키보드로 커밋 선택
- **WHEN** 사용자가 키보드만 사용해 커밋 목록으로 이동하고 합성 가능 커밋의 체크 상자를 조작한다
- **THEN** 시스템은 체크 상태를 변경하고 현재 키보드 위치를 계속 표시한다
- **AND** 현재 탐색 상태와 체크 상태를 각각 이름과 모양으로 구분한다

#### Scenario: 비동기 조회 후 위치 유지
- **WHEN** 브랜치 또는 이전 커밋을 불러오는 동안 사용자가 사용하던 컨트롤이 다시 표시된다
- **THEN** 시스템은 논리적으로 같은 컨트롤로 키보드 위치를 되돌린다

#### Scenario: 화면 200퍼센트 확대
- **WHEN** 사용자가 앱 화면을 200퍼센트까지 확대한다
- **THEN** 시스템은 저장소, 브랜치와 커밋의 주요 정보 및 조작 컨트롤을 가림 없이 탐색할 수 있게 표시한다

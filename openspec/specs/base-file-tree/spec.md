# base-file-tree Specification

## Purpose
비교 기준 시점의 추적 파일 전체를 조회해 저장소 구조를 계층으로 보여 주고, 그 안에서
변경 파일과 변경되지 않은 파일을 구분해 검토하게 한다. 조회는 커밋만 읽는다.

## Requirements

### Requirement: 비교 기준 경로 목록 조회
시스템은 Full Tree를 처음 표시할 때 비교 기준 커밋의 추적 경로 목록을 조회해야 한다(MUST).
같은 비교 범위에서는 다시 조회하지 않아야 하며(MUST NOT), 비교 범위가 바뀌면 이전 목록을
사용하지 않아야 한다(MUST NOT). 조회는 커밋만 읽어야 하며 작업 트리를 읽거나 바꾸지 않아야
한다(MUST NOT).

#### Scenario: Full Tree를 처음 열 때 조회
- **WHEN** 사용자가 Full Tree를 처음 선택한다
- **THEN** 시스템이 비교 기준 커밋의 추적 경로 목록을 조회한다
- **AND** 조회가 끝나면 전체 구조가 표시된다

#### Scenario: Full Tree를 열지 않은 검토
- **WHEN** 사용자가 결과를 만들고 Full Tree를 선택하지 않는다
- **THEN** 시스템은 경로 목록을 조회하지 않는다

#### Scenario: 같은 범위에서 다시 열기
- **WHEN** 사용자가 Full Tree를 떠났다가 같은 비교 범위에서 다시 선택한다
- **THEN** 시스템은 경로 목록을 다시 조회하지 않는다
- **AND** 전체 구조를 즉시 표시한다

#### Scenario: 결과를 다시 계산한 뒤
- **WHEN** 사용자가 같은 비교 범위에서 커밋 선택을 바꿔 결과를 다시 만든다
- **THEN** 시스템은 경로 목록을 다시 조회하지 않는다
- **AND** 파일 상태만 새 결과에 맞게 갱신한다

#### Scenario: 비교 범위 변경
- **WHEN** 사용자가 비교 범위를 다시 불러온다
- **THEN** 시스템은 이전 범위의 경로 목록을 표시하지 않는다
- **AND** Full Tree를 다시 열면 새 기준 커밋으로 조회한다

#### Scenario: 조회 중 저장소 상태
- **WHEN** 시스템이 경로 목록을 조회한다
- **THEN** 사용자의 branch, HEAD와 작업 트리 상태가 변하지 않는다

### Requirement: 저장소 전체 구조 표시
시스템은 Full Tree에서 비교 기준 경로와 통합 결과 경로를 합친 집합을 폴더 계층으로 표시해야
한다(MUST). 추적되지 않는 파일과 `.gitignore` 대상은 표시하지 않아야 한다(MUST NOT). 하위 항목이
폴더 하나뿐인 폴더가 이어지면 한 행에 경로로 합쳐야 한다(MUST).

#### Scenario: 변경 파일 주변 구조 확인
- **WHEN** 사용자가 Full Tree를 본다
- **THEN** 변경 파일이 속한 폴더와 그 폴더의 다른 파일이 함께 표시된다
- **AND** 각 파일은 저장소 상대 경로의 위치에 표시된다

#### Scenario: 추가된 파일의 위치
- **WHEN** 통합 결과가 비교 기준에 없던 파일을 추가한다
- **THEN** 그 파일이 자기 경로 위치에 표시된다
- **AND** 필요한 상위 폴더가 함께 표시된다

#### Scenario: 삭제된 파일의 위치
- **WHEN** 통합 결과가 비교 기준에 있던 파일을 삭제한다
- **THEN** 그 파일이 자기 경로 위치에 계속 표시된다

#### Scenario: 추적되지 않는 파일
- **WHEN** 저장소에 추적되지 않는 파일이나 `.gitignore` 대상 파일이 있다
- **THEN** Full Tree는 그 파일을 표시하지 않는다

#### Scenario: 단일 하위 폴더 경로 합치기
- **WHEN** 하위 항목이 폴더 하나뿐인 폴더가 연속으로 이어진다
- **THEN** 이어지는 폴더 이름이 하나의 행에 경로 형태로 함께 표시된다
- **AND** 해당 경로 전체가 한 단계만 들여쓰기된다

#### Scenario: 합쳐진 행의 접기
- **WHEN** 사용자가 합쳐진 경로 행을 접는다
- **THEN** 그 경로 아래의 하위 항목이 표시되지 않는다

#### Scenario: 하위 파일이 있는 폴더
- **WHEN** 폴더가 파일을 하나만 포함한다
- **THEN** 해당 폴더는 파일과 합쳐지지 않고 자신의 행으로 표시된다

### Requirement: 파일 상태 구분
시스템은 Full Tree의 각 파일을 추가, 수정, 삭제, 문제 또는 변경 없음으로 구분해야 한다(MUST).
변경 상태는 통합 결과에서 가져와야 하며(MUST), 결과에 없는 경로는 변경 없음으로 표시해야
한다(MUST).

#### Scenario: 변경 파일의 상태
- **WHEN** Full Tree에 통합 결과가 바꾼 파일이 표시된다
- **THEN** 그 파일의 상태가 다른 보기에서와 같은 추가, 수정 또는 삭제로 표시된다

#### Scenario: 변경 없는 파일의 상태
- **WHEN** Full Tree에 통합 결과가 건드리지 않은 파일이 표시된다
- **THEN** 그 파일이 변경 없음으로 구분되어 표시된다
- **AND** 사용자는 변경 상태와 구분해 인식할 수 있다

#### Scenario: 문제 파일의 상태
- **WHEN** 통합 결과에 문제 파일이 있다
- **THEN** Full Tree는 그 파일을 문제 상태로 표시한다

### Requirement: 변경을 품은 폴더 구분
시스템은 하위에 변경 파일이 하나라도 있는 폴더를 구분해 표시해야 한다(MUST). 폴더가 접혀
있을 때도 그 구분을 제공해야 한다(MUST). 합쳐진 경로 행은 그 경로 아래 전체를 보고 판정해야
한다(MUST).

#### Scenario: 변경이 있는 폴더
- **WHEN** 폴더의 하위 어딘가에 변경 파일이 있다
- **THEN** 그 폴더가 변경을 품은 폴더로 표시된다

#### Scenario: 변경이 없는 폴더
- **WHEN** 폴더의 하위에 변경 파일이 없다
- **THEN** 그 폴더는 변경을 품은 폴더로 표시되지 않는다

#### Scenario: 접힌 폴더의 구분
- **WHEN** 변경을 품은 폴더가 접혀 있다
- **THEN** 접힌 상태에서도 그 안에 변경이 있음을 확인할 수 있다

#### Scenario: 합쳐진 경로 행의 구분
- **WHEN** 합쳐진 경로 아래에 변경 파일이 있다
- **THEN** 그 합쳐진 행이 변경을 품은 폴더로 표시된다

### Requirement: 초기 접힘 상태
시스템은 Full Tree를 표시할 때 폴더를 접은 상태로 시작해야 하며(MUST), 변경 파일의 상위 폴더는
펼친 상태로 표시해야 한다(MUST). Full Tree의 접힘 상태는 Tree View의 접힘 상태와 분리해야
한다(MUST). 합쳐진 경로 행은 그 경로 아래에 변경 파일이 있으면 펼친 상태로 표시해야 한다(MUST).

#### Scenario: 처음 표시할 때
- **WHEN** 사용자가 Full Tree를 표시한다
- **THEN** 변경 파일까지 이어지는 폴더가 펼쳐져 변경 위치가 바로 보인다
- **AND** 변경이 없는 폴더는 접힌 상태로 표시된다

#### Scenario: 폴더 접고 펼치기
- **WHEN** 사용자가 Full Tree에서 폴더 행을 실행한다
- **THEN** 그 폴더의 하위 항목 표시가 바뀐다
- **AND** 선택 파일과 현재 diff는 변경되지 않는다

#### Scenario: 두 트리의 접힘 상태
- **WHEN** 사용자가 Tree View에서 폴더를 접고 Full Tree로 전환한다
- **THEN** Full Tree의 접힘 상태는 Tree View에서 접은 것과 무관하다

#### Scenario: 변경 파일이 합쳐진 경로 아래에 있을 때
- **WHEN** 변경 파일의 상위 폴더들이 하나의 행으로 합쳐진다
- **THEN** 그 합쳐진 행이 펼쳐진 상태로 표시된다

### Requirement: 경로 수 상한 안내
시스템은 표시할 경로 수에 상한을 두어야 하며(MUST), 상한을 넘으면 표시할 수 있는 범위와 상한에
도달한 사실을 함께 표시해야 한다(MUST). 넘친 경로를 조용히 버리지 않아야 한다(MUST NOT).

#### Scenario: 상한을 넘는 저장소
- **WHEN** 비교 기준의 추적 경로 수가 시스템 상한을 넘는다
- **THEN** 시스템은 상한까지의 경로로 전체 구조를 표시한다
- **AND** 상한에 도달했음과 사용자가 취할 수 있는 다음 행동을 표시한다

#### Scenario: 상한 안의 저장소
- **WHEN** 추적 경로 수가 상한 이내다
- **THEN** 시스템은 상한 안내를 표시하지 않는다

### Requirement: 변경되지 않은 파일 검토
시스템은 Full Tree에서 변경되지 않은 파일을 선택하면 비교 기준 시점의 내용을 읽기 전용으로
표시해야 한다(MUST). 내용은 선택 시점에 조회해야 하며(MUST), 선택 결과가 아님을 표시해야
한다(MUST).

#### Scenario: 변경 없는 파일 선택
- **WHEN** 사용자가 Full Tree에서 변경되지 않은 파일을 선택한다
- **THEN** 시스템이 비교 기준 시점의 파일 내용을 하나의 문서로 표시한다
- **AND** 그 내용이 선택 결과가 아님을 확인할 수 있다

#### Scenario: 선택하지 않은 파일
- **WHEN** 사용자가 Full Tree를 보고 어떤 변경 없는 파일도 선택하지 않는다
- **THEN** 시스템은 그 파일들의 내용을 조회하지 않는다

#### Scenario: 변경 파일 선택
- **WHEN** 사용자가 Full Tree에서 변경된 파일을 선택한다
- **THEN** 시스템은 다른 보기와 같은 diff를 표시한다

#### Scenario: 읽을 수 없는 파일 선택
- **WHEN** 사용자가 바이너리이거나 너무 큰 변경 없는 파일을 선택한다
- **THEN** 시스템은 원인과 사용자가 취할 수 있는 다음 행동을 표시한다
- **AND** Full Tree의 나머지 표시는 그대로 유지된다

### Requirement: 경로 목록 조회 실패 안내
시스템은 경로 목록을 조회하지 못하면 문제 범위, 원인과 다음 행동을 표시해야 한다(MUST).
실패해도 다른 보기는 계속 사용할 수 있어야 한다(MUST).

#### Scenario: 조회 실패
- **WHEN** 비교 기준 경로 목록 조회가 실패한다
- **THEN** 시스템은 전체 구조를 표시할 수 없음과 원인, 다음 행동을 표시한다
- **AND** 사용자는 Tree View, List View와 Config View를 계속 사용할 수 있다

#### Scenario: 조회 중 표시
- **WHEN** 경로 목록 조회가 진행 중이다
- **THEN** 시스템은 전체 구조를 준비 중임을 표시한다

### Requirement: 키보드로 전체 구조 탐색
시스템은 키보드만으로 Full Tree의 폴더를 이동하고 접고 펴며 파일을 선택할 수 있게 해야
한다(MUST). 각 폴더와 파일에 보이는 이름 또는 접근 가능한 이름을 제공해야 한다(MUST).

#### Scenario: 키보드로 폴더 접기
- **WHEN** 사용자가 Tab으로 Full Tree의 폴더 행에 포커스하고 Space 또는 Enter를 누른다
- **THEN** 그 폴더가 접히거나 펼쳐진다
- **AND** 포커스 위치와 펼침 상태를 확인할 수 있다

#### Scenario: 키보드로 파일 선택
- **WHEN** 사용자가 키보드로 Full Tree의 파일에 포커스하고 실행한다
- **THEN** 그 파일이 선택되고 검토 화면이 그 파일을 표시한다

# composite-diff-generation Specification

## Purpose
선형 이력에서 선택한 커밋만 반영된 최종 파일 상태와 하나의 통합 diff를
계산한다. 계산은 분리된 임시 작업 공간에서 수행하며 사용자의 branch, HEAD와
작업 트리 상태를 변경하지 않는다.

## Requirements

### Requirement: 선택과 독립적인 비교 기준
시스템은 기준 브랜치와 현재 작업 브랜치가 갈라진 지점을 비교 기준으로 확정해야 한다(SHALL). 확정된 비교 기준은 커밋 선택이 바뀌어도 변경되지 않아야 한다(SHALL).

#### Scenario: 선택 변경 후에도 같은 비교 기준 유지
- **WHEN** 사용자가 `feat(auth): validate login request`와 `feat(auth): persist session` 커밋을 선택해 결과를 확인한 뒤 문서 변경 커밋을 추가로 선택한다
- **THEN** 두 계산은 같은 분기 지점을 비교 기준으로 사용한다
- **AND** 선택한 첫 커밋의 부모를 새 비교 기준으로 사용하지 않는다

### Requirement: 선형 이력의 비연속 커밋 선택
시스템은 비교 기준의 후손이며 하나의 조상 관계에 있는 커밋을 서로 인접하지 않아도 선택할 수 있게 해야 한다(SHALL). 시스템은 선택 순서와 관계없이 커밋의 조상 관계에 따라 오래된 커밋부터 변경을 반영해야 한다(SHALL).

#### Scenario: 떨어진 커밋을 역순으로 선택
- **WHEN** 사용자가 선형 이력에서 `feat(auth): persist session`을 먼저 선택하고 그보다 오래된 `feat(auth): validate login request`를 나중에 선택한다
- **THEN** 시스템은 로그인 검증 변경을 먼저 반영하고 세션 저장 변경을 이어서 반영한다
- **AND** 두 커밋 사이의 미선택 리팩터링 커밋은 선택 목록에 포함하지 않는다

### Requirement: 선택 커밋만 반영된 통합 결과
시스템은 비교 기준에 선택한 커밋의 변경만 반영한 최종 파일 상태와 하나의 통합 diff를 제공해야 한다(SHALL). 미선택 커밋만이 만든 변경은 최종 파일 상태와 통합 diff에 포함하지 않아야 한다(MUST NOT).

#### Scenario: 미선택 변경 제외
- **WHEN** 로그인 검증, 내부 리팩터링, 세션 저장과 인증 문서 변경 커밋 중 로그인 검증과 세션 저장 커밋만 선택한다
- **THEN** 최종 파일 상태에는 선택한 로그인 검증과 세션 저장 변경이 포함된다
- **AND** 내부 리팩터링과 인증 문서 변경은 포함되지 않는다

#### Scenario: 파일 추가 수정 삭제 표현
- **WHEN** 선택한 커밋들이 텍스트 파일을 추가하고 기존 파일을 수정하며 다른 파일을 삭제한다
- **THEN** 최종 결과는 비교 기준에 대한 각 파일의 최종 추가, 수정과 삭제 상태를 보여준다
- **AND** 통합 diff는 각 파일의 최종 변경 내용을 보여준다

### Requirement: 같은 파일의 선택 변경 합성
시스템은 여러 선택 커밋이 같은 파일을 변경하면 선택된 모든 변경을 이력 순서대로 반영한 하나의 최종 파일 상태를 제공해야 한다(SHALL).

#### Scenario: 같은 인증 파일을 두 번 변경
- **WHEN** 오래된 선택 커밋이 로그인 입력 검증을 추가하고 이후 선택 커밋이 같은 파일에 세션 생성을 추가한다
- **THEN** 최종 파일에는 로그인 입력 검증과 세션 생성이 모두 반영된다
- **AND** 통합 diff에는 비교 기준에서 완성된 파일 상태까지의 변경이 한 번 표시된다

### Requirement: 최신 선택 결과 게시
시스템은 현재 선택과 일치하는 계산 결과만 현재 결과로 표시해야 한다(SHALL). 선택이 바뀐 뒤 완료된 이전 계산은 새 선택의 결과를 덮어쓰지 않아야 한다(MUST NOT).

#### Scenario: 이전 계산이 늦게 완료됨
- **WHEN** 첫 선택의 계산 중 사용자가 선택을 변경하고 새 계산이 시작된 뒤 첫 계산이 늦게 완료된다
- **THEN** 첫 계산의 결과는 현재 결과로 표시되지 않는다
- **AND** 현재 결과는 새 선택과 일치하거나 새 계산 중임을 나타낸다

#### Scenario: 모든 선택 해제
- **WHEN** 사용자가 선택한 커밋을 모두 해제한다
- **THEN** 시스템은 이전 통합 결과를 현재 결과에서 제거한다
- **AND** 결과를 만들려면 하나 이상의 커밋을 선택해야 함을 안내한다

### Requirement: 사용자 Git 작업 상태 보존
시스템은 결과 계산의 성공, 실패와 취소 후에도 사용자의 현재 브랜치, HEAD,
staged 변경, unstaged 변경, untracked 파일과 저장소 메타데이터를 계산 전과
동일하게 유지해야 한다(SHALL).

#### Scenario: 작업 중인 저장소에서 계산 성공
- **WHEN** 현재 저장소에 staged 변경, unstaged 변경과 untracked 파일이 있는 상태에서 선택 결과 계산이 성공한다
- **THEN** 현재 브랜치와 HEAD는 계산 전과 같다
- **AND** staged 변경, unstaged 변경과 untracked 파일의 내용 및 상태도 계산 전과 같다

#### Scenario: 변경 적용 실패 후 상태 보존
- **WHEN** 선택 변경을 합성하는 중 Git 오류가 발생한다
- **THEN** 현재 브랜치, HEAD와 작업 중인 모든 파일 상태는 계산 전과 같다

#### Scenario: 계산 취소 후 상태 보존
- **WHEN** 사용자가 진행 중인 계산을 취소한다
- **THEN** 현재 브랜치, HEAD와 작업 중인 모든 파일 상태는 계산 전과 같다
- **AND** 취소된 계산의 결과는 현재 결과로 표시되지 않는다

#### Scenario: 저장소 메타데이터 보존
- **WHEN** 결과 계산 전 원본 저장소에 로컬 Git 설정과 다른 worktree 등록이 있다
- **THEN** 성공, 실패와 취소 뒤 로컬 Git 설정과 worktree 등록이 계산 전과 같다
- **AND** 시스템은 이번 요청의 임시 작업 공간만 제거한다

### Requirement: 동일 입력의 결과 일관성
시스템은 저장소 상태, 비교 기준과 선택 커밋 집합이 같으면 운영체제의 작업
트리 텍스트 변환 설정과 관계없이 반복 계산에서 동일한 최종 파일 상태와 통합
diff를 제공해야 한다(SHALL).

#### Scenario: 같은 선택 반복 계산
- **WHEN** 저장소를 변경하지 않고 같은 비교 기준과 커밋을 여러 번 선택해 계산한다
- **THEN** 각 계산의 파일 순서, 최종 파일 내용과 통합 diff가 동일하다

#### Scenario: Windows 작업 트리 줄바꿈 변환
- **WHEN** Windows의 작업 트리 줄바꿈 변환 설정이 임시 파일 내용에 적용될 수 있다
- **THEN** 시스템은 Git index의 최종 객체 내용과 같은 텍스트를 결과로 제공한다
- **AND** 반복 계산의 파일 내용과 통합 diff가 바뀌지 않는다

### Requirement: Git 적용 오류 구분
시스템은 선택 커밋을 적용할 때 실제 파일 충돌과 그 밖의 Git 실행 실패를
구분해야 한다(MUST). 사용자가 취할 다음 행동은 확인된 실패 종류와 일치해야
한다(MUST).

#### Scenario: 병합되지 않은 파일이 있는 일반 충돌
- **WHEN** 선택 커밋 적용이 일반 충돌 종료 코드 1로 실패하고 임시 index에 병합되지 않은 파일이 있다
- **THEN** 시스템은 독립 적용할 수 없는 커밋을 식별한다
- **AND** 필요한 이전 커밋을 함께 선택한 뒤 다시 실행하도록 안내한다

#### Scenario: 파일 충돌이 아닌 Git 실행 실패
- **WHEN** 선택 커밋 적용이 일반 충돌 종료 코드 외의 상태나 파일 잠금, 권한 또는 저장 장치 문제로 실패한다
- **THEN** 시스템은 해당 실패를 커밋 충돌로 표시하지 않는다
- **AND** 원래 Git 실패 범위에 맞는 진단과 재시도 행동을 제공한다

### Requirement: 비교 범위를 벗어난 선택 안내
시스템은 선택한 커밋이 이번 변경에서 지원하는 비교 범위를 벗어나면 현재 선택에 대한 완성된 결과를 표시하지 않아야 한다(MUST NOT). 시스템은 문제가 발생한 커밋, 원인 및 사용자가 취할 수 있는 다음 행동을 제공해야 한다(SHALL).

#### Scenario: 비교 기준의 후손이 아닌 커밋 선택
- **WHEN** 선택한 커밋 중 하나가 확정된 비교 기준의 후손이 아니다
- **THEN** 시스템은 해당 커밋을 식별하고 현재 비교 범위에서 선택할 수 없음을 안내한다
- **AND** 사용자가 비교 기준이나 선택을 변경할 수 있게 안내한다

## ADDED Requirements

### Requirement: 일관된 데스크톱 시각 언어
시스템은 지정된 graphite 색상, 보라색 강조색과 Git 상태 색상을 중앙 디자인
토큰으로 사용해야 한다(MUST). 사용자에게 보이는 기본 화면 문구는 영어로
제공해야 한다(MUST).

#### Scenario: 작업대 기본 화면 표시
- **WHEN** 사용자가 데스크톱 앱을 연다
- **THEN** 앱 배경, 패널, 구분선, 선택과 포커스가 지정된 색상 토큰으로 표시된다
- **THEN** 저장소 열기와 주요 작업 문구가 영어로 표시된다

#### Scenario: Git 상태 표시
- **WHEN** 변경 파일에 추가, 수정 또는 삭제 상태가 있다
- **THEN** 시스템은 상태별 색상과 문자 또는 아이콘을 함께 표시한다

### Requirement: 연속된 검토 작업 흐름
시스템은 사용자가 저장소를 열고 비교 범위와 커밋을 선택한 뒤 변경 파일과
좌우 diff를 검토할 수 있는 연속된 작업 흐름을 제공해야 한다(SHALL).

#### Scenario: 저장소에서 diff까지 검토
- **WHEN** 사용자가 유효한 로컬 저장소를 열고 비교 범위와 커밋을 선택해 비교를 실행한다
- **THEN** 시스템은 선택된 커밋 수와 변경 파일을 표시한다
- **THEN** 사용자가 변경 파일을 선택하면 해당 파일의 기준과 선택 결과 diff를 표시한다

#### Scenario: 첫 실행
- **WHEN** 열린 저장소가 없는 상태에서 앱을 실행한다
- **THEN** 시스템은 저장소를 여는 주요 행동과 필요한 짧은 안내를 표시한다
- **THEN** 저장소 자료가 필요한 다른 행동은 실행 가능한 상태로 표시하지 않는다

#### Scenario: 결과에 변경 파일이 없음
- **WHEN** 통합 결과에 변경 파일이 없다
- **THEN** 시스템은 결과가 비어 있음을 변경 파일 영역에 표시한다
- **THEN** 사용자가 비교 범위 또는 커밋 선택을 변경할 수 있게 한다

### Requirement: 작업 상태와 복구 행동
시스템은 저장소 조회, 비교 범위 조회와 결과 계산의 진행 상태 및 문제 범위를
해당 작업 맥락에서 표시해야 한다(MUST). 복구할 수 있는 오류에는 사용자가
실행할 다음 행동을 제공해야 한다(MUST).

#### Scenario: 결과 계산 취소
- **WHEN** 사용자가 진행 중인 결과 계산을 취소한다
- **THEN** 시스템은 계산이 취소되었음을 표시한다
- **THEN** 사용자가 현재 선택으로 계산을 다시 실행할 수 있게 한다

#### Scenario: Git 실행 실패
- **WHEN** Git 실행 또는 결과 계산이 실패한다
- **THEN** 시스템은 실패한 작업과 문제 범위를 설명한다
- **THEN** 시스템은 다시 시도하거나 저장소를 다시 여는 복구 행동을 제공한다

#### Scenario: 비교 범위가 오래됨
- **WHEN** 조회 뒤 브랜치가 이동해 현재 비교 범위를 사용할 수 없다
- **THEN** 시스템은 오래된 결과를 현재 결과로 표시하지 않는다
- **THEN** 시스템은 비교 범위를 다시 불러오는 행동을 제공한다

### Requirement: 비동기 응답 격리
시스템은 저장소 또는 비교 범위가 변경된 뒤 이전 요청의 응답을 현재 화면에
적용하지 않아야 한다(MUST).

#### Scenario: 저장소 전환 중 이전 응답 도착
- **WHEN** 사용자가 다른 저장소를 연 뒤 이전 저장소의 요청이 완료된다
- **THEN** 시스템은 이전 저장소의 커밋, 변경 파일과 diff를 표시하지 않는다

#### Scenario: 계산 취소 뒤 완료 응답 도착
- **WHEN** 사용자가 계산을 취소한 뒤 취소된 요청의 완료 응답이 도착한다
- **THEN** 시스템은 해당 응답을 현재 결과로 표시하지 않는다

### Requirement: 접근 가능한 작업대
시스템은 키보드로 주요 작업을 수행할 수 있게 해야 하며(MUST), 보이는 이름,
포커스 표시와 상태 알림을 제공해야 한다(MUST).

#### Scenario: 키보드 검토
- **WHEN** 사용자가 키보드만 사용해 앱을 탐색한다
- **THEN** 저장소, 비교 범위, 커밋, 변경 파일과 diff 동작에 순서대로 접근할 수 있다
- **THEN** 현재 포커스와 선택 상태를 시각적으로 확인할 수 있다

#### Scenario: 고대비 모드
- **WHEN** 운영체제가 forced-colors 모드를 사용한다
- **THEN** 주요 컨트롤의 포커스와 선택 상태가 운영체제 색상으로 구분된다

### Requirement: 화면 크기와 확대 대응
시스템은 1280×720과 1920×1080 화면에서 주요 검토 작업을 제공해야 하며
(MUST), 200% 확대에서도 핵심 정보와 행동에 접근할 수 있어야 한다(MUST).

#### Scenario: 1280×720 작업
- **WHEN** 앱 창이 1280×720 크기로 표시된다
- **THEN** 사용자는 저장소, 커밋, 변경 파일과 diff의 주요 동작에 접근할 수 있다
- **THEN** 긴 경로와 제목이 다른 작업 영역을 화면 밖으로 밀어내지 않는다

#### Scenario: 200% 확대
- **WHEN** 사용자가 화면을 200%로 확대한다
- **THEN** 작업 영역은 읽고 탐색할 수 있는 순서로 배치된다
- **THEN** 핵심 동작이 잘리거나 가려지지 않는다

### Requirement: Git 작업 상태 보존
시스템은 검토 작업의 성공, 실패와 취소 흐름에서 사용자의 branch, HEAD,
staged, unstaged와 untracked 상태를 변경하지 않아야 한다(MUST).

#### Scenario: 검토 작업 완료
- **WHEN** 사용자가 커밋을 선택하고 통합 결과를 검토한다
- **THEN** 작업 전후의 branch, HEAD와 작업 트리 상태가 동일하다

#### Scenario: 검토 작업 실패 또는 취소
- **WHEN** 결과 계산이 실패하거나 사용자가 계산을 취소한다
- **THEN** 작업 전후의 branch, HEAD와 작업 트리 상태가 동일하다

## Context

검토 영역은 renderer의 CSS grid 한 줄로 구성되어 있고, `Changed Files` 열의
폭이 스타일에 고정되어 있다. 좁은 화면에서는 같은 영역이 위아래 배치로 바뀌는
규칙이 이미 있고, 1280×720에서 검토 영역이 화면 높이의 70% 이상을 차지해야
한다는 기존 요구사항도 유지해야 한다.

폭 조절은 사용자가 자주 반복하는 조작이므로 조작 중 화면이 끊기지 않아야 하고,
키보드 사용자와 보조 기술 사용자도 같은 결과를 얻을 수 있어야 한다.

## Goals / Non-Goals

**Goals:**

- 마우스와 키보드로 `Changed Files`와 diff 영역의 폭을 조절한다.
- 두 영역 모두 사용할 수 있는 최소 폭을 항상 보장한다.
- 조절한 폭을 검토 작업이 이어지는 동안 유지한다.
- 좁은 화면의 세로 배치 규칙과 기존 높이 요구사항을 깨지 않는다.

**Non-Goals:**

- 앱을 다시 실행한 뒤에도 폭을 복원하는 저장 기능.
- 세로 방향 영역 높이 조절과 패널 위치 재배치.
- activity rail, 작업 바와 상태 표시줄의 크기 조절.

## Decisions

### 결정 1: 구분자를 grid의 독립된 열로 둔다

검토 영역 grid를 `변경 파일 폭 | 구분자 | 나머지` 세 열로 구성하고, 첫 열의
폭만 사용자 값으로 바꾼다. 구분자는 실제 열을 차지하며 두 패널과 겹치지
않는다. 좁은 화면에서는 세로 배치용 열 정의가 적용된다.

### 결정 2: 폭은 CSS 사용자 지정 속성으로만 전달한다

폭 값은 검토 영역에 사용자 지정 속성으로 넣고, 열 정의 자체는 스타일 파일에
남긴다. 화면 크기별 열 정의는 스타일 규칙이 관리하고 사용자 값은 변경 파일
열의 폭에만 적용한다.

### 결정 3: 끌기는 포인터 캡처로 처리한다

구분자를 누른 시점에 포인터를 구분자에 고정해, 포인터가 구분자를 벗어나도
이동과 놓기 이벤트를 계속 받는다. 조절 상태는 구분자 안에서 관리하고 포인터를
놓거나 취소하면 해제한다.

### 결정 4: 최소 폭은 두 영역 모두를 기준으로 계산한다

`Changed Files`의 절대 최소·최대 폭과 함께, diff 영역이 유지해야 하는 최소
폭을 검토 영역 전체 폭에서 빼서 실제 최대값을 정한다. 검토 영역 폭을 아직 알
수 없는 시점에는 절대 최대값만 적용한다. 결과 영역이 표시되면 실제 폭으로
최대값을 다시 계산한다.

### 결정 5: 구분자는 window splitter 규약을 따른다

구분자에 분리자 역할, 세로 방향, 현재 폭과 최소·최대 폭, 조절 대상과 이름을
부여하고 포커스를 받을 수 있게 한다. 방향키는 한 단계 조절, Home과 End는
양끝으로 이동한다. 보조 기술은 현재 폭과 조절 범위를 읽을 수 있다.

### 결정 6: diff 안쪽 구분자는 편집기 기능을 사용한다

기준과 결과 사이 폭 조절은 diff 편집기가 제공하는 분할 조절 기능을 명시적으로
켜서 제공한다. 편집기가 스크롤, 줄 정렬과 분할 폭을 함께 관리한다.

## Risks / Trade-offs

- 포인터 캡처를 지원하지 않는 테스트 환경 → 테스트 환경에 동작 없는 대체
  구현을 두고, 실제 앱 검증은 Playwright Electron 끌기 조작으로 확인한다.
- 사용자가 폭을 극단으로 조절해 한쪽이 좁아짐 → 결정 4의 최소 폭 계산으로
  두 영역 모두 사용 가능한 범위만 허용한다.
- 조절한 폭 때문에 좁은 화면에서 가로 스크롤 발생 → 좁은 화면에서는 구분자를
  숨기고 세로 배치 규칙을 그대로 사용한다.
- 폭을 저장하지 않으므로 앱을 다시 열면 기본값으로 돌아간다 → 이번 범위에서는
  의도된 동작이며, 필요해지면 별도 change에서 다룬다.

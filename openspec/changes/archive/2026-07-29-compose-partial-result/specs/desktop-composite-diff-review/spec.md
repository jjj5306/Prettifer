## MODIFIED Requirements

### Requirement: 변경 파일 목록 탐색
시스템은 성공한 통합 결과의 파일을 저장소 상대 경로 순서로 표시하고 추가, 수정과 삭제 상태를 구분해야 한다(SHALL). 문제 파일은 같은 목록의 원래 경로 위치에서 문제 상태로 구분해야 한다(MUST).

#### Scenario: 여러 변경 파일 확인
- **WHEN** 통합 결과에 추가, 수정 또는 삭제된 파일이 있다
- **THEN** 시스템은 각 파일의 저장소 상대 경로와 변경 상태를 안정적인 경로 순서로 표시한다
- **AND** 첫 번째 파일을 기본 탐색 대상으로 표시한다

#### Scenario: 키보드로 파일 변경
- **WHEN** 사용자가 키보드로 다른 변경 파일을 선택한다
- **THEN** 시스템은 파일 목록의 현재 위치와 선택 파일을 표시한다
- **AND** 파일 검토 화면을 선택한 파일 내용으로 갱신한다

#### Scenario: 문제 파일이 포함된 목록
- **WHEN** 통합 결과에 문제 파일이 있다
- **THEN** 시스템은 문제 파일을 경로 순서상 원래 위치에 표시한다
- **AND** 추가, 수정, 삭제와 구분되는 문제 상태로 표시한다
- **AND** 보조 기술에 그 파일이 문제 상태임을 알린다

## ADDED Requirements

### Requirement: 부분 결과 상태 표시
시스템은 문제 파일이 있는 결과를 완전한 결과와 구분해 표시해야 한다(MUST). 부분 결과에는 문제 파일 수와 해당 파일로 이동하는 수단을 제공해야 한다(MUST).

#### Scenario: 부분 결과 확인
- **WHEN** 문제 파일이 있는 통합 결과가 표시된다
- **THEN** 시스템은 결과가 실행 가능성이 검증되지 않은 부분 결과임을 표시한다
- **AND** 문제 파일 수를 함께 표시한다

#### Scenario: 문제 요약에서 문제 파일로 이동
- **WHEN** 사용자가 부분 결과의 문제 요약에서 이동 수단을 실행한다
- **THEN** 시스템은 첫 문제 파일을 선택 상태로 만든다
- **AND** 그 파일의 문제 내용을 검토 영역에 표시한다

#### Scenario: 완전한 결과 확인
- **WHEN** 문제 파일이 없는 통합 결과가 표시된다
- **THEN** 시스템은 부분 결과 표시와 문제 요약을 표시하지 않는다

### Requirement: 문제 파일 검토 화면
시스템은 문제 파일을 선택했을 때 완성된 diff 대신 문제 원인과 다음 행동을 표시해야 한다(MUST).

#### Scenario: 문제 파일 선택
- **WHEN** 사용자가 목록에서 문제 파일을 선택한다
- **THEN** 시스템은 좌우 diff를 표시하지 않는다
- **AND** 문제 원인, 관련 커밋과 사용자가 취할 다음 행동을 표시한다

#### Scenario: 문제 파일에서 정상 파일로 이동
- **WHEN** 사용자가 문제 파일을 본 뒤 정상 파일을 선택한다
- **THEN** 시스템은 그 파일의 좌우 diff를 표시한다

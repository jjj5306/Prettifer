## ADDED Requirements

### Requirement: 표시 폭보다 긴 경로 행
시스템은 파일 행의 경로가 행의 표시 폭보다 길면 파일 이름과 그 파일이 속한 폴더를
줄이지 않고 표시해야 하며(MUST), 그 위 폴더만 줄여 생략 표시와 함께 나타내야 한다
(MUST). 줄인 폴더와 파일 이름은 서로 구분되게 표시해야 한다(MUST). 행에서 전체 경로를
확인할 수 있어야 한다(MUST).

#### Scenario: 깊은 경로의 변경 파일
- **WHEN** 변경 파일의 저장소 상대 경로가 행의 표시 폭보다 길다
- **THEN** 파일 이름과 그 파일이 속한 폴더가 줄지 않고 표시된다
- **THEN** 그 위 폴더는 줄어들며 생략 표시로 잘린 위치를 알린다

#### Scenario: 같은 폴더를 공유하는 여러 행
- **WHEN** 여러 변경 파일이 같은 긴 폴더 경로를 공유한다
- **THEN** 각 행에서 서로 다른 부분인 폴더와 파일 이름을 읽고 구분할 수 있다

#### Scenario: 줄인 경로의 전체 확인
- **WHEN** 사용자가 줄여 표시된 행을 확인한다
- **THEN** 행에서 전체 저장소 상대 경로를 확인할 수 있다

#### Scenario: 폴더가 없는 행
- **WHEN** 행이 폴더 없이 이름만 표시한다
- **THEN** 시스템은 이름을 그대로 표시한다

## MODIFIED Requirements

### Requirement: 접근 가능한 보기 토글
시스템은 키보드로 Tree View, List View, Config View와 Full Tree를 선택할 수 있게 해야 하며
(MUST), 각 토글에 보이는 이름과 선택 상태를 제공해야 한다(MUST). 네 토글은 서로 구분되는
아이콘을 표시해야 하며(MUST), 두 토글이 같은 아이콘을 사용하지 않아야 한다(MUST NOT).

#### Scenario: 키보드로 보기 변경
- **WHEN** 사용자가 Tab으로 보기 토글에 포커스하고 Space 또는 Enter를 누른다
- **THEN** 포커스한 보기가 활성화된다
- **THEN** 포커스 위치와 활성 보기를 확인할 수 있다

#### Scenario: 보기 전환 뒤 파일 탐색
- **WHEN** 사용자가 키보드로 보기를 전환한 뒤 변경 파일 영역으로 이동한다
- **THEN** 선택 파일 또는 첫 탐색 가능한 파일에서 검토를 계속할 수 있다

#### Scenario: 토글별 아이콘 구분
- **WHEN** 사용자가 `Changed Files` 머리글의 보기 토글을 본다
- **THEN** Tree View, List View, Config View와 Full Tree가 각각 다른 아이콘으로 표시된다
- **THEN** 사용자는 누르기 전에 각 토글이 어떤 보기인지 아이콘과 이름으로 구분할 수 있다

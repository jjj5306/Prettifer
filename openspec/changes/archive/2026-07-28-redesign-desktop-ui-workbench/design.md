## Context

현재 Electron renderer는 저장소 도구 모음, 커밋 이력, 변경 파일과 Monaco diff를
React 컴포넌트로 제공한다. 화면 상태는 reducer의 구분된 상태로 관리되고,
Electron 기능은 typed preload API를 통해 호출된다.

새 목업은 graphite 색상, 보라색 강조색, 높은 정보 밀도와 영어 문구를 제품의
시각 기준으로 정의한다. 두 목업은 동일한 `Changed Files` 자료를 Tree View와
List View로 전환하는 상태를 보여 준다. 패널 구성과 세부 크기는 실제 사용 흐름,
화면 크기와 확대 검증 결과에 맞춰 조정한다.

## Goals / Non-Goals

**Goals:**

- 저장소부터 통합 diff까지 이어지는 흐름을 하나의 데스크톱 작업대로 구성한다.
- 색상과 상태 표현을 중앙 디자인 토큰으로 관리한다.
- 사용자 노출 문구를 영어로 제공한다.
- 변경 파일을 Tree View와 List View로 전환하고 선택 맥락을 유지한다.
- 화면 상태, 키보드 접근성과 오류 복구를 자동화된 테스트로 보호한다.
- 현재 Electron 보안 경계와 Git 작업 상태 보존 계약을 유지한다.

**Non-Goals:**

- 생성형 목업 HTML의 런타임 도입
- 파일 편집, stage, commit과 push
- 원격 저장소 관리
- 충돌 자동 해결
- 다중 창과 자동 업데이트
- 외부 네트워크에서 런타임 글꼴 불러오기

## Decisions

### 디자인 토큰

renderer 최상위 스타일에 색상, 간격, 테두리, 포커스와 상태 토큰을 정의한다.
기능별 CSS Module은 토큰을 참조한다. 앱 배경은 `#111317`, 기본 패널은
`#171A1F`, 구분선은 `#2B3038`, 주요 선택색은 `#8F80FA`를 사용한다.
Git 추가, 삭제와 수정 상태는 각각 `#5BB98C`, `#E06C75`, `#F9BC45`를
사용하고 문자 또는 아이콘을 함께 표시한다.

UI 글꼴은 앱 패키지에 포함한 Hanken Grotesk를 사용한다. 코드, 경로와 SHA는
앱 패키지에 포함한 Geist와 Monaco의 monospace 체계를 사용한다. 글꼴을
외부 URL에서 불러오지 않으며 패키지 실행과 오프라인 실행에서 같은 결과를
제공한다.

### 작업대 구성

앱 화면은 상단 앱 바, 저장소와 비교 범위 도구 모음, 좌측 activity rail,
커밋 선택, 변경 파일과 diff, 하단 작업 상태로 구성한다. activity rail의
항목은 현재 제공되는 저장소, 커밋, 변경 파일과 diff 영역으로 이동한다.
activity rail은 앱 콘텐츠의 가장 왼쪽 열 전체를 차지하고 앱 바와 저장소
도구 모음보다 위에서 시작한다. 사용자가 항목을 실행하면 해당 영역에 포커스를
이동하고 선택한 항목을 현재 메뉴로 유지한다.
각 영역은 독립적인 스크롤 경계를 갖고 긴 경로와 제목이 다른 영역의 너비를
밀어내지 않게 한다.

레이아웃은 1280×720과 1920×1080에서 주요 흐름을 제공한다. 200% 확대에서는
영역을 순서대로 탐색할 수 있는 단일 열 또는 축소된 패널 구성을 적용한다.
기본 화면에서는 저장소 범위, Commit History와 Selected Result를 한 줄 중심의
작업 바로 압축한다. 선택 결과가 준비된 1280×720 화면에서는 변경 파일과 diff
검토 영역이 화면 높이의 70% 이상을 차지한다. 변경 파일 패널은 탐색에 필요한
고정 범위를 사용하고 diff가 결과 영역의 대부분을 차지한다. UI와 코드 글자,
컨트롤과 activity 아이콘은 현재 밀도를 유지하는 범위에서 한 단계 크게 표시한다.

Commit History는 비교 범위의 커밋을 시간순으로 배치해 가장 오래된 커밋을
왼쪽에, 가장 최신 커밋을 오른쪽에 표시한다. 커밋 적용 순서와 화면 탐색 순서가
같아지며, 페이지 추가 로드는 현재 선택과 검사 상태를 유지한다.

### 화면 상태

저장소, 비교 범위와 계산 상태는 현재 reducer의 구분된 상태를 사용한다.
화면 계산값은 원본 상태에서 구한다. 로딩, 빈 결과, 취소, 오래된 범위와 오류는
해당 작업 영역에 표시하고, 사용자가 실행할 수 있는 복구 행동을 함께 제공한다.

사용자 동작은 이벤트 처리 함수에서 시작한다. Electron 구독과 Monaco model은
Effect에서 연결하고 종료 시 해제한다.

선택 가능한 커밋의 체크박스와 카드 본문은 같은 다중 선택 함수를 사용한다.
카드 본문을 선택하면 해당 커밋을 상세 탐색 대상으로도 표시한다. merge commit
처럼 선택할 수 없는 항목은 상세 탐색만 허용하고 선택 수를 변경하지 않는다.

### 선택 결과 계산

선택 결과는 임시 Git worktree에서 계산한다. 대형 저장소 전체를 checkout하지
않도록 `--no-checkout` worktree를 만든 뒤 기준 tree로 index를 초기화하고,
선택 커밋의 변경 경로만 sparse checkout한다. 변경 경로는 각 선택 커밋을
rename 해석 없이 비교해 이전 경로와 새 경로를 모두 포함한다.

커밋은 비교 범위의 시간 순서로 적용한다. 선택 커밋이 선택하지 않은 이전
커밋에서 생성된 파일을 수정하는 등 독립 적용할 수 없으면 해당 커밋 ID와
이전 필수 커밋을 함께 선택하라는 복구 행동을 제공한다. Git stderr와 임시
경로는 renderer에 노출하지 않는다.

결과의 numstat에서 추가 및 삭제 줄 수가 모두 `-`인 경로는 바이너리로
표시한다. 바이너리 내용은 문자열로 읽거나 IPC로 전달하지 않고, diff 영역에는
텍스트 비교를 제공할 수 없다는 상태를 표시한다.

임시 worktree 제거에 실패하면 임시 디렉터리를 정리한 뒤 만료 기준을 현재
시점으로 지정해 stale worktree 등록을 prune한다. 성공, 실패와 취소 뒤
Prettifer 임시 worktree가 저장소에 남지 않는지 검증한다.

### 변경 파일 보기

보기 모드는 renderer의 표시 상태로 관리한다. 통합 결과의 파일 배열과 선택된
저장소 상대 경로는 기존 결과 및 앱 상태를 사용한다. 보기 전환은 결과를 다시
계산하거나 IPC 요청을 만들지 않는다.

Tree View는 저장소 상대 경로를 디렉터리 구간으로 나눠 화면용 계층을 계산한다.
각 파일 노드는 원본 상대 경로를 식별자로 유지한다. List View는 원본 상대
경로를 한 행에 표시한다. 두 보기는 동일한 선택 함수와 파일 상태 표현을
공유한다.

토글은 두 개의 이름 있는 버튼과 `aria-pressed` 상태로 제공한다. Tab으로
토글에 접근하고 Space 또는 Enter로 보기를 선택할 수 있다. 전환 뒤 선택 파일,
현재 diff와 키보드 포커스 맥락을 유지한다.

### 컴포넌트 경계

앱 셸은 화면 영역 배치와 상태 전달을 담당한다. 저장소, 커밋, 변경 파일과
diff 컴포넌트는 각 기능의 표현과 사용자 이벤트를 담당한다. 경로 계층 계산은
변경 파일 기능 안의 순수 함수로 두고 컴포넌트 테스트에서 검증한다.

표시 문자열과 작은 변환은 실제로 둘 이상의 호출자가 같은 의미로 사용할 때만
공유한다. 목업 전용 계층과 범용 UI helper는 추가하지 않는다.

### 검증

React 테스트는 디자인 토큰 계약, 영어 문구, 상태별 행동, 파일 보기 전환,
선택 유지와 키보드 동작을 검증한다. Playwright Electron은 실제 저장소를 열어
커밋을 선택하고 결과를 만든 뒤 두 파일 보기와 diff를 확인한다.

실제 앱 화면은 Tree View와 List View에서 캡처한다. 테스트는 renderer 콘솔
오류, 처리되지 않은 Promise와 사용자 Git 상태 변경 여부도 확인한다.

## Risks / Trade-offs

- [높은 정보 밀도로 작은 화면에서 내용이 잘릴 수 있음] → 패널별 최소 너비,
  독립 스크롤과 확대 환경 검증을 적용한다.
- [경로 계층 계산이 파일 선택 식별자를 바꿀 수 있음] → 모든 노드가 원본 저장소
  상대 경로를 유지하고 그 경로로 선택한다.
- [전역 스타일 변경이 기존 접근성 상태를 약화할 수 있음] → focus-visible,
  forced-colors와 reduced-motion 테스트를 유지한다.
- [목업의 정적 자료와 실제 비동기 상태가 어긋날 수 있음] → 주요 흐름을 실제
  Electron 앱과 Git fixture로 검증한다.

## Migration Plan

1. 현재 사용자 흐름과 오류 상태를 회귀 테스트로 고정한다.
2. 디자인 토큰과 앱 작업대 구조를 적용한다.
3. 영어 문구와 상태별 안내를 적용한다.
4. 변경 파일 Tree/List 전환과 선택 유지 테스트를 구현한다.
5. Playwright Electron으로 실제 흐름과 두 화면을 검증한다.
6. 사용하지 않는 이전 스타일과 화면 코드를 제거한다.

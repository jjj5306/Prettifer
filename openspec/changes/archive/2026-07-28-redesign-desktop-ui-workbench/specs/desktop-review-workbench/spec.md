## ADDED Requirements

### Requirement: 일관된 데스크톱 시각 언어
시스템은 지정된 graphite 색상, 보라색 강조색과 Git 상태 색상을 중앙 디자인
토큰으로 사용해야 한다(MUST). 사용자에게 보이는 기본 화면 문구는 영어로
제공해야 한다(MUST).

#### Scenario: 작업대 기본 화면 표시
- **WHEN** 사용자가 데스크톱 앱을 연다
- **THEN** 앱 배경, 패널, 구분선, 선택과 포커스가 지정된 색상 토큰으로 표시된다
- **THEN** 저장소 열기와 주요 작업 문구가 영어로 표시된다

#### Scenario: Git 상태 표시
- **WHEN** 변경 파일에 추가, 수정 또는 삭제 상태가 있다
- **THEN** 시스템은 상태별 색상과 문자 또는 아이콘을 함께 표시한다

#### Scenario: 오프라인 타이포그래피
- **WHEN** 네트워크 연결 없이 데스크톱 앱을 실행한다
- **THEN** UI 문구는 앱에 포함된 Hanken Grotesk로 표시된다
- **THEN** 경로, SHA와 코드 문구는 앱에 포함된 Geist 또는 Monaco monospace로 표시된다

### Requirement: 작업대 activity rail
시스템은 목업의 좌측 activity rail을 제공하고 저장소, 커밋, 변경 파일과 diff
검토 영역으로 이동할 수 있게 해야 한다(MUST). 각 항목은 보이는 아이콘과
접근 가능한 영어 이름을 제공해야 한다(MUST).

#### Scenario: 커밋 영역으로 이동
- **WHEN** 사용자가 activity rail의 Commit History 항목을 실행한다
- **THEN** 키보드 포커스가 Commit History 영역으로 이동한다
- **THEN** 현재 작업 영역을 시각적으로 확인할 수 있다

#### Scenario: 메뉴 선택 유지
- **WHEN** 사용자가 사용할 수 있는 activity rail 항목을 실행한다
- **THEN** 실행한 항목이 현재 메뉴로 표시된다
- **THEN** 다른 항목을 실행할 때까지 선택 표시가 유지된다

#### Scenario: 전체 높이 메뉴 영역
- **WHEN** 데스크톱 작업대가 표시된다
- **THEN** activity rail은 앱 콘텐츠의 가장 왼쪽 열에서 상단부터 하단까지 표시된다
- **THEN** 앱 바, 저장소 도구 모음과 검토 영역은 activity rail의 오른쪽에 표시된다

#### Scenario: 결과 전용 영역
- **WHEN** 선택 결과가 아직 만들어지지 않았다
- **THEN** 변경 파일과 diff activity 항목은 사용할 수 없는 상태로 표시된다
- **THEN** 저장소와 커밋 항목은 계속 사용할 수 있다
- **THEN** 사용할 수 없는 항목은 현재 메뉴로 표시되지 않는다

### Requirement: 연속된 검토 작업 흐름
시스템은 사용자가 저장소를 열고 비교 범위와 커밋을 선택한 뒤 변경 파일과
좌우 diff를 검토할 수 있는 연속된 작업 흐름을 제공해야 한다(SHALL).

#### Scenario: 저장소에서 diff까지 검토
- **WHEN** 사용자가 유효한 로컬 저장소를 열고 비교 범위와 커밋을 선택해 비교를 실행한다
- **THEN** 시스템은 선택된 커밋 수와 변경 파일을 표시한다
- **THEN** 사용자가 변경 파일을 선택하면 해당 파일의 기준과 선택 결과 diff를 표시한다

#### Scenario: 새로 추가된 파일 선택
- **WHEN** 사용자가 통합 결과에서 새로 추가된 파일을 선택한다
- **THEN** 시스템은 기준 revision이 없는 파일임을 표시한다
- **THEN** 시스템은 기준 내용을 표시하지 않고 파일 전체 내용을 한 번만 표시한다
- **THEN** 표시된 모든 줄이 추가된 내용으로 구분된다

#### Scenario: 바이너리 파일 선택
- **WHEN** 사용자가 통합 결과의 바이너리 파일을 선택한다
- **THEN** 시스템은 바이너리 파일을 텍스트나 코드로 해석하지 않는다
- **THEN** 시스템은 해당 파일에 텍스트 diff를 표시할 수 없음을 안내한다

#### Scenario: 커밋 카드 탐색
- **WHEN** 사용자가 커밋 카드 본문을 실행한다
- **THEN** 해당 커밋만 현재 탐색 대상으로 표시된다
- **AND** 합성 선택과 선택 수는 변경되지 않는다

#### Scenario: 커밋 합성 선택
- **WHEN** 사용자가 서로 다른 커밋 카드의 합성 선택 컨트롤을 실행한다
- **THEN** 선택한 커밋의 체크 상태와 선택 수가 갱신된다

#### Scenario: 커밋 이력 시간순 표시
- **WHEN** 사용자가 비교 범위를 불러온다
- **THEN** Commit History의 가장 오래된 커밋이 왼쪽에 표시된다
- **THEN** 가장 최신 커밋이 오른쪽에 표시된다

#### Scenario: 커밋 카드 한 줄 표시
- **WHEN** Commit History에 커밋 카드가 표시된다
- **THEN** 제목, 짧은 커밋 ID, 작성 월일과 작성자가 한 줄에 표시된다
- **THEN** 폭이 부족하면 작성자 이름부터 줄어들고 짧은 커밋 ID와 작성 월일은 계속 읽을 수 있다
- **THEN** 사용자는 전체 제목, 전체 커밋 ID, 작성자, 전체 작성 시각과 선택할 수 없는 이유를 접근 가능한 이름으로 확인할 수 있다

#### Scenario: 선택할 수 없는 커밋 카드
- **WHEN** 사용자가 merge commit처럼 선택할 수 없는 커밋 카드 본문을 실행한다
- **THEN** 시스템은 해당 카드를 현재 탐색 대상으로 표시한다
- **THEN** 제목, 전체 커밋 ID, 작성자와 전체 작성 시각을 카드에서 확인할 수 있다
- **THEN** 선택된 커밋 목록과 선택 수는 변경하지 않는다

#### Scenario: 첫 실행
- **WHEN** 열린 저장소가 없는 상태에서 앱을 실행한다
- **THEN** 시스템은 저장소를 여는 주요 행동과 필요한 짧은 안내를 표시한다
- **THEN** 저장소 자료가 필요한 다른 행동은 실행 가능한 상태로 표시하지 않는다

#### Scenario: 결과에 변경 파일이 없음
- **WHEN** 통합 결과에 변경 파일이 없다
- **THEN** 시스템은 결과가 비어 있음을 변경 파일 영역에 표시한다
- **THEN** 사용자가 비교 범위 또는 커밋 선택을 변경할 수 있게 한다

### Requirement: 작업 상태와 복구 행동
시스템은 저장소 조회, 비교 범위 조회와 결과 계산의 진행 상태 및 문제 범위를
해당 작업 맥락에서 표시해야 한다(MUST). 복구할 수 있는 오류에는 사용자가
실행할 다음 행동을 제공해야 한다(MUST).

#### Scenario: 결과 계산 취소
- **WHEN** 사용자가 진행 중인 결과 계산을 취소한다
- **THEN** 시스템은 계산이 취소되었음을 표시한다
- **THEN** 사용자가 현재 선택으로 계산을 다시 실행할 수 있게 한다

#### Scenario: Git 실행 실패
- **WHEN** Git 실행 또는 결과 계산이 실패한다
- **THEN** 시스템은 실패한 작업과 문제 범위를 설명한다
- **THEN** 시스템은 다시 시도하거나 저장소를 다시 여는 복구 행동을 제공한다

#### Scenario: 이전 변경에 의존하는 커밋
- **WHEN** 선택한 커밋이 선택하지 않은 이전 커밋에서 생성된 파일을 수정해 독립 적용할 수 없다
- **THEN** 시스템은 적용할 수 없는 커밋을 식별한다
- **THEN** 시스템은 필요한 이전 커밋을 함께 선택한 뒤 다시 실행하도록 안내한다

#### Scenario: 대형 저장소 결과 계산
- **WHEN** 사용자가 대형 저장소에서 일부 커밋을 선택해 결과를 만든다
- **THEN** 시스템은 선택 커밋이 변경하는 경로만 임시 작업 공간에 준비한다
- **AND** 저장소 전용 merge 또는 filter driver가 다른 저장소 파일을 요구하면 격리된 임시 작업 공간에 해당 저장소 내용을 준비한다
- **THEN** 성공, 실패 또는 취소 뒤 임시 작업 공간이 저장소에 남지 않는다

#### Scenario: 비교 범위가 오래됨
- **WHEN** 조회 뒤 브랜치가 이동해 현재 비교 범위를 사용할 수 없다
- **THEN** 시스템은 오래된 결과를 현재 결과로 표시하지 않는다
- **THEN** 시스템은 비교 범위를 다시 불러오는 행동을 제공한다

### Requirement: 비동기 응답 격리
시스템은 저장소 또는 비교 범위가 변경된 뒤 이전 요청의 응답을 현재 화면에
적용하지 않아야 한다(MUST).

#### Scenario: 저장소 전환 중 이전 응답 도착
- **WHEN** 사용자가 다른 저장소를 연 뒤 이전 저장소의 요청이 완료된다
- **THEN** 시스템은 이전 저장소의 커밋, 변경 파일과 diff를 표시하지 않는다

#### Scenario: 계산 취소 뒤 완료 응답 도착
- **WHEN** 사용자가 계산을 취소한 뒤 취소된 요청의 완료 응답이 도착한다
- **THEN** 시스템은 해당 응답을 현재 결과로 표시하지 않는다

### Requirement: 접근 가능한 작업대
시스템은 키보드로 주요 작업을 수행할 수 있게 해야 하며(MUST), 보이는 이름,
포커스 표시와 상태 알림을 제공해야 한다(MUST).

#### Scenario: 키보드 검토
- **WHEN** 사용자가 키보드만 사용해 앱을 탐색한다
- **THEN** 저장소, 비교 범위, 커밋, 변경 파일과 diff 동작에 순서대로 접근할 수 있다
- **THEN** 현재 포커스와 선택 상태를 시각적으로 확인할 수 있다

#### Scenario: 고대비 모드
- **WHEN** 운영체제가 forced-colors 모드를 사용한다
- **THEN** 주요 컨트롤의 포커스와 선택 상태가 운영체제 색상으로 구분된다

### Requirement: 화면 크기와 확대 대응
시스템은 1280×720과 1920×1080 화면에서 주요 검토 작업을 제공해야 하며
(MUST), 200% 확대에서도 핵심 정보와 행동에 접근할 수 있어야 한다(MUST).

#### Scenario: 1280×720 작업
- **WHEN** 앱 창이 1280×720 크기로 표시된다
- **THEN** 사용자는 저장소, 커밋, 변경 파일과 diff의 주요 동작에 접근할 수 있다
- **THEN** 긴 경로와 제목이 다른 작업 영역을 화면 밖으로 밀어내지 않는다
- **THEN** 선택 결과가 준비되면 변경 파일과 diff 검토 영역에 화면 높이의 70% 이상이 제공된다
- **THEN** diff 편집기는 제목과 상태 줄을 제외한 diff 검토 영역 전체를 채운다
- **THEN** 저장소 범위, Commit History와 Selected Result는 한 줄 중심의 압축된 작업 바로 표시된다
- **THEN** 앱 바, 저장소 범위, Commit History와 Selected Result의 세로 길이가 서로 같다
- **THEN** diff의 코드 글자와 줄 번호를 편안하게 읽을 수 있다

#### Scenario: 200% 확대
- **WHEN** 사용자가 화면을 200%로 확대한다
- **THEN** 작업 영역은 읽고 탐색할 수 있는 순서로 배치된다
- **THEN** 핵심 동작이 잘리거나 가려지지 않는다

### Requirement: Git 작업 상태 보존
시스템은 검토 작업의 성공, 실패와 취소 흐름에서 사용자의 branch, HEAD,
staged, unstaged와 untracked 상태를 변경하지 않아야 한다(MUST).

#### Scenario: 검토 작업 완료
- **WHEN** 사용자가 커밋을 선택하고 통합 결과를 검토한다
- **THEN** 작업 전후의 branch, HEAD와 작업 트리 상태가 동일하다

#### Scenario: 검토 작업 실패 또는 취소
- **WHEN** 결과 계산이 실패하거나 사용자가 계산을 취소한다
- **THEN** 작업 전후의 branch, HEAD와 작업 트리 상태가 동일하다

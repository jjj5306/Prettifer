## Why

지금 저장소를 열려면 앱을 띄우고 폴더 대화상자에서 경로를 다시 찾아 들어가야 한다. 터미널에서
저장소를 오가며 일하는 사람에게는 이미 알고 있는 경로를 다시 고르는 작업이다.

부수적으로 검증 간극이 하나 있다. 이슈 #10에서 E2E 전용 진입점을 분리한 뒤 운영 진입점에는
저장소를 주입할 방법이 없어졌고, 패키지 smoke 테스트가 배포 산출물이 실제로 통합 결과를 만드는
것까지는 확인하지 못한다. 명령행 인자는 테스트용 우회가 아닌 제품 경로로 그 간극을 메운다.

## What Changes

- 앱 시작 시 명령행 인자로 받은 경로를 열 대상으로 삼는다.
- 인자가 없으면 지금과 같이 아무 저장소도 열지 않은 상태로 시작한다.
- 인자가 유효한 Git 저장소가 아니면 조용히 무시하지 않고 화면에 진단을 표시한다.
- 인자 경로도 폴더 선택과 같은 검증(경로 정규화, Git 저장소 확인)을 지난다.
- 패키지 smoke 테스트가 이 경로로 전체 검토 흐름을 다시 검증한다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `desktop-repository-navigation`: `로컬 Git 저장소 열기`에 시작 시 명령행 인자로 저장소를 여는
  동작과, 인자가 없거나 유효하지 않을 때의 결과를 추가한다.

## Impact

- `src/desktop/main/`: 인자 해석, 시작 시 저장소 열기 경로
- `src/desktop/shared/`: 시작 저장소 조회 계약 추가
- `src/desktop/preload/`: 새 계약 노출
- `src/desktop/renderer/`: 시작 시 한 번 조회하고 기존 저장소 상태 전이를 재사용
- `test/e2e/desktop-package-smoke.e2e.ts`: 전체 흐름 재확인
- Git·합성 코어는 변경하지 않는다

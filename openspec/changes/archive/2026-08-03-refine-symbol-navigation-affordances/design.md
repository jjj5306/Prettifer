## Context

검토 화면은 Monaco를 손으로 선언한 최소 인터페이스(`MonacoApi`)로만 다룬다. 정의 이동은 Monaco
언어 제공자를 등록하지 않고 편집기 이벤트(`onMouseDown`, `onKeyDown`)로 받는다. 이 결정 덕분에
검토 영역에 무엇을 띄울지와 이동 이력은 앱 상태가 결정한다.

그 결정의 대가가 이번 이슈다. 제공자를 등록하면 Monaco가 링크 표시(`gotoDefinitionWithMouse`)를
공짜로 해 주지만, 등록하지 않았으므로 표시도 직접 해야 한다.

## Goals / Non-Goals

**Goals:**

- 지금 보고 있는 파일이 화면에 있다.
- Ctrl을 누르면 이동 가능한 심볼이 보인다.
- 이동하면 선언된 그 자리에 멈추고, 멈춘 곳이 보인다.

**Non-Goals:**

- Monaco 언어 제공자 등록으로 전환하지 않는다. 이동 이력과 검토 대상 결정을 Monaco에 넘기게 된다.
- 심볼 판정 정확도는 바꾸지 않는다. 멤버 선언 인식은 이미 동작한다.
- 링크 표시를 툴팁(정의 미리보기)까지 확장하지 않는다.

## Decisions

### 1. 머리글은 파일 경로만 남긴다

머리글은 `제목 · 설명` 두 칸이다. 설명 자리에 파일 경로를 넣는다.

| 상태 | 제목 | 오른쪽 |
|---|---|---|
| 수정·삭제 | `Side-by-side Diff` | `src/app/Caller.java` |
| 추가 | `Added File` | `src/app/New.java` |
| 선택 결과 밖 | `Outside the Selected Result` | `src/model/UtVar.java` |

좌우 배치 설명(`Base on the left · selected result on the right`)은 뺀다. 제목이 이미 좌우
비교임을 말하고, 화면 자체가 두 칸으로 보인다. 추가 파일의 "every line is part of the selected
result"는 제목과 초록 배경이 이미 말한다.

접근성 이름은 그대로 둔다. 편집기의 `aria-label`은 파일 경로와 무엇을 비교하는지를 계속
포함하므로, 화면에서 설명이 빠져도 보조 기술 사용자가 잃는 정보는 없다.

### 2. 링크 표시는 장식 컬렉션 하나를 갱신한다

Monaco의 `createDecorationsCollection`이 돌려주는 컬렉션을 붙잡고 `set`/`clear`로 갱신한다.
매번 새 컬렉션을 만들면 이전 표시가 남는다.

| 입력 | 처리 |
|---|---|
| `onMouseMove` | 마지막 위치를 기억하고, Ctrl/Cmd가 눌린 상태면 그 위치의 식별자를 표시 |
| `onKeyDown`, `onKeyUp` | 마지막 위치로 다시 판정. Ctrl을 누르기만 해도 표시가 나타난다 |
| 식별자 아님, Ctrl 아님 | 표시를 지운다 |

식별자 범위는 이미 있는 `symbolAt`이 돌려주는 `startColumn`, `endColumn`을 쓴다. 클릭 처리와
같은 함수를 쓰므로 표시된 범위와 실제로 이동하는 대상이 어긋나지 않는다.

밑줄과 커서는 CSS 클래스 하나(`prettifer-symbol-link`)로 준다. Monaco의 `inlineClassName`은
장식 범위에만 적용되므로 줄 전체가 아니라 식별자만 링크로 보인다.

### 3. 이동은 줄이 아니라 위치로 한다

지금 이동은 `{ line }`만 전달하고 `column: 1`에 커서를 둔다. 선언 줄의 심볼 열을 함께 전달한다.

열은 **renderer가 계산한다.** 검색 결과 항목(`SymbolHitDto`)에 그 줄 내용이 이미 있으므로,
`symbolAt`을 그 줄에 적용하면 열이 나온다. main에 열을 요구해 경계 계약을 넓힐 이유가 없고,
사용자가 목록에서 고른 항목에도 같은 계산이 그대로 쓰인다.

도착 표시는 줄 전체 장식(`prettifer-target-line`)으로 한다. 다음 이동이나 다른 파일 선택 때
새 장식이 이전 것을 대체한다. 시간이 지나면 사라지는 표시는 쓰지 않는다. 타이머는 검증하기
어렵고, 스크롤을 되돌린 뒤에도 어디였는지 남아 있는 편이 검토에 낫다.

## Risks / Trade-offs

- [장식이 남는다] → 링크 표시와 도착 표시는 각각 컬렉션 하나만 쓰고, 편집기를 버릴 때 함께
  버린다. 표시가 겹쳐 쌓이지 않는 것을 테스트로 고정한다.
- [머리글에서 설명이 사라져 처음 쓰는 사용자가 좌우 의미를 모른다] → 제목이 `Side-by-side Diff`이고
  접근성 이름에 남는다. 파일 경로가 매 순간 필요한 정보라는 점을 우선한다.
- [Ctrl 링크 표시가 Monaco 자체 링크(URL 등)와 섞여 보일 수 있다] → 밑줄 색을 강조색으로 두어
  구분한다. 두 표시가 같은 자리에 겹칠 일은 식별자와 URL이 겹치지 않으므로 없다.

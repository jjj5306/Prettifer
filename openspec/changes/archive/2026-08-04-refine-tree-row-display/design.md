## Context

두 트리는 같은 CSS 모듈을 쓴다. 행은 `<button>`이고, 앱 전역 스타일이 모든 버튼에 테두리, 둥근
모서리와 표면 배경을 준다.

```
.app button { border: 1px solid var(--color-border); border-radius: 0.25rem; background: … }
.file       { border-color: transparent; background: transparent; }
```

`.app button`은 클래스와 타입 선택자라 명시도가 `.file`보다 높다. 그래서 행이 지정한 투명 테두리가
지고, 모든 행이 테두리 있는 알약으로 그려진다. 지금 화면은 결정의 결과가 아니라 충돌의 결과다.

들여쓰기는 중첩된 `<ul>`의 `margin-left`와 `padding-left`를 합쳐 레벨당 약 1.9rem이고, 계층선은
각 행의 `::before`와 `::after`로 그린다. 행은 `width: fit-content`다.

Tree View는 `joinSingleChildDirectories`로 단일 하위 폴더 경로를 한 행에 합친다. Full Tree의
`buildFullTree`에는 그 단계가 없다.

## Goals / Non-Goals

**Goals:**

- 깊이 15, 파일 17,807개 저장소에서 두 트리를 읽을 수 있게 한다.
- 파일 탐색기에서 기대하는 행 표시에 맞춘다.
- 변경 상태, 선택 파일과 접근 가능한 이름은 그대로 유지한다.

**Non-Goals:**

- 파일 아이콘
- 행 가상 스크롤
- Config View의 그룹 목록 표시
- 다른 패널의 시각 언어

## Decisions

### 1. 행은 버튼이지만 버튼처럼 보이지 않게 한다

행을 `<button>`이 아닌 요소로 바꾸는 방법을 먼저 검토했다. 그러면 키보드 활성화와 접근 가능한 이름을
직접 다시 만들어야 한다. 지금은 기본 컨트롤이 그것을 해 주고 있고, 그 이점을 표현 때문에 버릴 이유가
없다.

그래서 요소는 그대로 두고 표시만 바꾼다. 전역 버튼 스타일을 이기도록 행 선택자에 패널 클래스를
더한다. 전역 규칙을 약화시키는 대신 트리 쪽에서 이기게 하는 이유는, 다른 화면의 버튼은 지금 모습이
맞기 때문이다.

### 2. 계층선을 없애고 들여쓰기만 남긴다

계층선은 얕은 트리에서는 관계를 읽는 데 도움이 되지만, 깊은 트리에서는 선이 화면을 채워 이름을
가린다. 파일 탐색기가 선 없이 들여쓰기만 쓰는 것과 같은 이유다.

들여쓰기는 레벨당 한 단계로 줄인다. 중첩 목록의 `margin-left` 한 값만 쓰고, 계층선을 그리던
`padding-left`와 두 가상 요소를 없앤다.

### 3. 행은 패널 너비를 채우고 이름은 경계에서 자른다

내용 너비 행은 목록을 들쭉날쭉하게 만들고, 가리킴과 선택을 이름 길이만큼만 칠한다. 파일 탐색기는
행 전체를 띠로 칠한다. 그 편이 어느 행에 있는지 읽기 쉽다.

패널을 가로로 스크롤하지 않는다. 이름이 길면 잘리고, 전체 경로는 이미 접근 가능한 이름과 tooltip에
있다. 가로 스크롤은 트리를 옆으로 밀어 세로로 훑는 동작을 방해한다.

### 4. Full Tree도 Tree View와 같은 규칙으로 경로를 합친다

하위가 폴더 하나뿐인 폴더가 이어지면 한 행에 경로로 합친다. Tree View가 이미 그렇게 한다. 두 트리가
같은 저장소를 다르게 접는 이유가 없다.

Full Tree에서는 이 합치기가 더 중요하다. 변경 파일만 담는 트리와 달리 저장소 전체를 담으므로 단일
하위 폴더 사슬이 훨씬 길다.

합친 행은 사슬에서 가장 깊은 폴더의 경로를 자기 정체성으로 삼는다. 접힘 상태와 변경 포함 판정이
그 경로를 키로 쓰므로, 합치기가 상태를 잃게 하지 않는다.

### 5. 변경을 품은 폴더 표시는 유지한다

행이 평평해지면서 색만으로 구분하던 것이 약해진다. 변경을 품은 폴더는 표식을 계속 유지하고, 접힌
상태에서도 보이게 한다. 이 판정은 합쳐진 행에서도 사슬 아래 전체를 본다.

## Risks / Trade-offs

- [계층선을 없애 얕은 트리의 관계가 덜 드러난다] → 들여쓰기 단계와 폴더 굵기로 계층을 표현한다.
  깊은 트리에서 얻는 가독성이 얕은 트리에서 잃는 것보다 크다.
- [행 높이를 줄여 클릭 목표가 작아진다] → 행이 패널 너비를 채우므로 가로 목표는 오히려 넓어진다.
- [이름이 잘려 전체 경로를 화면에서 못 읽는다] → 접근 가능한 이름과 tooltip이 전체 경로를 계속
  제공한다. 이 요구사항은 이미 있고 바꾸지 않는다.
- [전역 버튼 스타일을 이기려고 선택자를 더한다] → 트리 행에만 적용되는 국소적인 예외다. 전역 규칙을
  바꾸면 다른 화면의 버튼이 함께 바뀐다.

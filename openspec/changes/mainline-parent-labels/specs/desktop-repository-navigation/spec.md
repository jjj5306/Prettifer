## ADDED Requirements

### Requirement: merge 기준 부모 선택 표시
시스템은 merge commit의 기준 부모를 고르는 목록에서 각 부모가 병합받은 쪽인지 병합해 들여온
쪽인지와 그 부모 커밋의 짧은 ID, 제목을 함께 표시해야 한다(MUST). 첫 부모만 병합받은 쪽으로
표시해야 한다(MUST). 부모의 순서 번호는 화면에 표시하지 않아야 한다(MUST NOT). 선택한 기준 부모를
알리는 문구도 순서 번호가 아니라 어느 쪽인지로 표현해야 한다(MUST).

#### Scenario: 부모가 둘인 merge의 선택 목록
- **WHEN** 사용자가 부모가 둘인 merge commit의 기준 부모 목록을 연다
- **THEN** 시스템은 첫 부모를 병합받은 쪽으로, 나머지 부모를 병합해 들여온 쪽으로 표시한다
- **AND** 각 부모의 짧은 ID와 제목을 함께 표시한다
- **AND** 부모의 순서 번호는 표시하지 않는다

#### Scenario: 부모가 셋 이상인 merge의 선택 목록
- **WHEN** 사용자가 부모가 셋 이상인 merge commit의 기준 부모 목록을 연다
- **THEN** 시스템은 첫 부모만 병합받은 쪽으로 표시한다
- **AND** 나머지 부모를 모두 병합해 들여온 쪽으로 표시한다

#### Scenario: 선택한 기준 부모 확인
- **WHEN** 사용자가 merge commit의 기준 부모를 고른 상태다
- **THEN** 시스템은 그 커밋이 어느 쪽 부모를 기준으로 하는지 알린다
- **AND** 부모의 순서 번호로 알리지 않는다

#### Scenario: 제목이 긴 부모 커밋
- **WHEN** 기준 부모 중 제목이 선택 목록에 담기지 못할 만큼 긴 커밋이 있다
- **THEN** 시스템은 그 제목을 줄여 표시한다
- **AND** 선택 컨트롤의 너비는 제목 길이에 따라 달라지지 않는다
- **AND** 목록을 열면 각 항목의 전체 문구를 보여준다

#### Scenario: 기준 부모 선택이 있는 좁은 커밋 행
- **WHEN** merge commit 행에 기준 부모 선택과 커밋 정보를 함께 담을 폭이 없다
- **THEN** 시스템은 커밋 정보를 잘라 표시한다
- **AND** 어느 정보도 다른 정보 위에 겹쳐 표시하지 않는다
- **AND** 기준 부모 선택과 그 라벨은 줄이지 않는다

## MODIFIED Requirements

### Requirement: 선형 커밋 흐름 탐색
시스템은 현재 지원 범위에 맞게 작업 브랜치의 첫 번째 부모를 따라가는 선형
커밋 흐름을 가장 오래된 커밋부터 최신 커밋 순서로 표시해야 한다(SHALL). 추가로 불러온 커밋이
있으면 첫 페이지 상태로 되돌리는 초기화를 제공해야 한다(MUST). 그 초기화는 저장소를 다시 읽지
않아야 한다(MUST NOT).

#### Scenario: 커밋 정보 확인
- **WHEN** 선택한 비교 범위에 커밋이 있다
- **THEN** 시스템은 각 커밋의 짧은 ID, 제목, 작성자와 작성 시각을 가장 오래된 커밋부터 최신 커밋 순서로 표시한다
- **AND** 합성할 수 있는 커밋에 선택 컨트롤을 제공한다

#### Scenario: merge commit 확인
- **WHEN** 선형 흐름에 부모가 둘 이상인 merge commit이 포함된다
- **THEN** 시스템은 해당 커밋이 merge commit임을 표시한다
- **AND** 해당 행에서 기준 부모를 고르는 컨트롤을 제공한다

#### Scenario: 비교 범위에 커밋이 없음
- **WHEN** 공통 조상 이후 작업 브랜치에 표시할 커밋이 없다
- **THEN** 시스템은 현재 비교 범위에 선택할 커밋이 없음을 표시한다
- **AND** 다른 브랜치 범위를 선택하는 행동을 안내한다

#### Scenario: 이전 커밋 추가 로딩
- **WHEN** 현재 페이지보다 오래된 커밋이 있고 사용자가 이전 커밋을 더 불러온다
- **THEN** 시스템은 이미 표시된 커밋, 체크 상태와 현재 키보드 위치를 유지한 채 다음 커밋 페이지를 추가한다

#### Scenario: 불러온 커밋 초기화
- **WHEN** 추가 페이지를 불러온 상태에서 사용자가 불러온 커밋 초기화를 실행한다
- **THEN** 시스템은 첫 페이지에 담겼던 커밋만 표시한다
- **AND** 저장소를 다시 읽지 않는다
- **AND** 커밋 선택은 그대로 유지한다

#### Scenario: 초기화 뒤 다시 불러오기
- **WHEN** 사용자가 불러온 커밋을 초기화한 뒤 다시 이전 커밋을 더 불러온다
- **THEN** 시스템은 초기화 이전과 같은 다음 페이지를 추가한다

#### Scenario: 되돌릴 커밋이 없음
- **WHEN** 첫 페이지만 불러온 상태다
- **THEN** 시스템은 불러온 커밋 초기화를 제공하지 않는다

#### Scenario: 조회 중 브랜치 이동
- **WHEN** 화면을 연 뒤 작업 브랜치가 다른 커밋을 가리키도록 변경된다
- **THEN** 시스템은 현재 목록이 최신 브랜치 상태와 다름을 표시한다
- **AND** 사용자가 새 이력을 불러오기 전에는 기존 커밋을 새 결과의 입력으로 사용하지 않는다

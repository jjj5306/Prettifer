## 1. 코어 개발 기반

- [x] 1.1 TypeScript 코어의 package, build, type check, lint와 test 실행 구성을 추가하고 각 명령이 빈 프로젝트에서 성공하는지 확인한다.
- [x] 1.2 편집기 API에 의존하지 않는 코어 소스와 테스트 디렉터리 경계를 만들고 의존성 방향을 검사할 수 있게 구성한다.
- [x] 1.3 지원되는 Git 실행 파일을 확인하고 사용할 수 없을 때 설치 또는 설정 방법을 안내하는 실패 테스트를 먼저 작성한다.
- [x] 1.4 Git 실행 환경 확인 동작을 구현해 1.3 테스트를 통과시킨다.

## 2. 실제 Git 테스트 fixture

- [x] 2.1 의미 있는 커밋 별칭, 선형 이력과 기준 브랜치를 재현하는 fixture builder의 실패 테스트를 작성한다.
- [x] 2.2 로그인 검증, 내부 리팩터링, 세션 저장과 문서 변경 커밋을 가진 임시 Git 저장소 fixture를 구현한다.
- [x] 2.3 같은 파일의 순차 변경과 파일 추가·수정·삭제 이력을 만드는 fixture 테스트를 먼저 작성한다.
- [x] 2.4 2.3 시나리오와 staged, unstaged, untracked 작업 상태를 준비하고 정확히 비교하는 fixture 기능을 구현한다.

## 3. 안전한 Git 실행과 합성 작업 공간

- [x] 3.1 Git 인자 전달, 비대화형 설정, 종료 코드, 표준 오류와 취소 전달을 검증하는 실패 테스트를 작성한다.
- [x] 3.2 프로세스와 파일 시스템 세부사항을 감싼 Git 실행 경계를 구현해 3.1 테스트를 통과시킨다.
- [x] 3.3 성공, 적용 실패, 취소와 동시 요청에서 임시 작업 공간의 분리 및 정리를 검증하는 실패 테스트를 작성한다.
- [x] 3.4 비교 기준에서 요청별 임시 작업 공간을 생성하고 모든 종료 경로에서 제거하는 수명 주기를 구현한다.
- [x] 3.5 Windows 파일 잠금으로 정리가 지연될 때 제한된 재시도와 잔여 경로 진단을 검증하는 테스트를 작성하고 구현한다.

## 4. 비교 기준과 선택 순서

- [x] 4.1 기준 브랜치와 작업 브랜치의 공통 조상을 확정하고 선택 변경 후에도 유지하는 실패 테스트를 작성한다.
- [x] 4.2 선택과 독립적인 비교 기준 확정 동작을 구현해 4.1 테스트를 통과시킨다.
- [x] 4.3 비연속 커밋의 역순 선택, 기준 후손 검증과 조상 순서 정렬을 검증하는 실패 테스트를 작성한다.
- [x] 4.4 선택 커밋 검증과 오래된 커밋부터의 안정적인 정렬을 구현해 4.3 테스트를 통과시킨다.

## 5. 선택 변경 합성과 통합 diff

- [x] 5.1 비연속 선택에서 미선택 리팩터링과 문서 변경이 최종 결과에 포함되지 않는 실패 테스트를 작성한다.
- [x] 5.2 선택한 변경만 임시 작업 공간에 순서대로 반영하고 비교 기준과의 최종 파일 상태 및 통합 diff를 생성한다.
- [x] 5.3 같은 인증 파일을 두 선택 커밋이 변경할 때 하나의 최종 상태로 합성되는 실패 테스트를 작성한다.
- [x] 5.4 같은 파일의 선택 변경을 누적해 5.3 테스트를 통과시킨다.
- [x] 5.5 텍스트 파일의 최종 추가, 수정과 삭제 상태 및 diff 표현을 검증하는 실패 테스트를 작성한다.
- [x] 5.6 파일 추가, 수정과 삭제의 최종 상태 계산을 구현해 5.5 테스트를 통과시킨다.
- [x] 5.7 동일 입력을 반복 계산했을 때 파일 순서, 파일 내용과 통합 diff가 같은지 검증하는 실패 테스트를 작성한다.
- [x] 5.8 환경별 출력 설정과 정렬을 고정해 5.7 테스트를 통과시킨다.

## 6. 요청 전환과 오류 안내

- [x] 6.1 계산 중 선택 변경, 이전 계산의 지연 완료와 모든 선택 해제 시나리오의 실패 테스트를 작성한다.
- [x] 6.2 계산 세대와 취소를 관리해 최신 선택의 결과만 현재 결과로 게시하고 선택이 없으면 이전 결과를 제거한다.
- [x] 6.3 기준 범위 밖 커밋에서 해당 커밋, 원인과 다음 행동을 제공하는 실패 테스트를 작성한다.
- [x] 6.4 비교 범위를 벗어난 선택의 진단을 구현하고 실패 결과가 완성된 현재 결과로 표시되지 않게 한다.
- [x] 6.5 성공, 실패와 취소 전후의 브랜치, HEAD, staged, unstaged와 untracked 상태가 같은지 확인하는 인수 테스트를 작성하고 통과시킨다.

- [x] 7.2 요구사항 시나리오와 인수 테스트의 대응 관계를 점검하고 누락된 회귀 테스트를 추가한다.
- [x] 7.3 test, type check, lint와 build 전체 검증을 실행하고 결과를 기록한다.
- [x] 7.4 `openspec validate build-composite-diff-core --strict`를 통과시키고 실제 완료 상태에 맞게 작업 체크리스트를 갱신한다.

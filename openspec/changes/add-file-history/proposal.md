## Why

현재 파일 검토 화면은 선택한 커밋의 통합 결과만 보여 주므로, 선택 파일이 어떤
커밋과 경로 변경을 거쳐 현재 상태가 되었는지 확인하기 어렵다. 사용자가 통합
결과를 떠나지 않고 파일의 전체 흐름과 결과에 기여한 커밋을 추적할 수 있어야 한다.

## What Changes

- 선택 파일의 이력을 대상 브랜치에서 확인 가능한 오래된 커밋부터 현재 상태까지
  표시한다.
- 이름 변경으로 확인된 이전·현재 경로를 하나의 파일 계보로 연결하고, 삭제 후 같은
  경로에 다시 생성된 파일은 별도 계보로 구분한다.
- 통합 대상으로 선택되어 해당 파일에 정상 적용된 커밋을 기여 커밋으로 강조하고,
  충돌로 제외된 커밋은 문제 상태로 구분한다.
- 파일 이력의 커밋을 실행하면 같은 diff 영역에서 그 커밋의 변경을 임시로 검토하고,
  통합 결과로 돌아갈 때 기존 파일과 탐색 위치를 복원한다.
- 얕은 복제에서는 확인 가능한 이력을 계속 제공하면서 범위, 원인과 다음 행동을
  안내하고, 신뢰할 수 있는 부분 결과가 없으면 오류로 표시한다.
- 변경 파일, 변경되지 않은 파일, 바이너리 파일과 문제 파일에 같은 파일 이력
  진입점을 제공하고 바이너리 변경은 내용 대신 메타데이터를 표시한다.
- 파일 이력을 지연 조회하고 100개 단위로 추가하며, 파일·범위·저장소 변경 시 오래된
  요청 결과가 현재 화면에 적용되지 않게 한다.
- Activity Rail에 File History 탐색 항목을 추가하고 키보드만으로 목록 탐색, 변경
  열기와 통합 결과 복귀를 지원한다.

## Capabilities

### New Capabilities

- `file-history`: 선택 파일의 경로 계보, 기여 상태, 커밋별 변경 검토, 부분 이력과
  키보드 탐색을 정의한다.

### Modified Capabilities

- `desktop-review-workbench`: Activity Rail과 왼쪽 탐색 영역에 File History 진입 및
  Changed Files와의 전환 동작을 추가한다.

## Impact

- Git 파일 이력과 커밋별 파일 변경을 읽는 main 프로세스 서비스가 추가된다.
- main, preload와 renderer 사이의 파일 이력 요청·응답 계약이 추가된다.
- 데스크톱 상태 관리에 지연 조회, 페이지 추가, 캐시, 임시 diff와 복귀 상태가
  추가된다.
- Activity Rail, 왼쪽 탐색 패널과 diff 검토 화면의 탐색 흐름이 확장된다.
- 파일 이력, rename, merge, 얕은 복제, 바이너리, 취소·오래된 응답과 키보드 흐름을
  검증하는 단위·통합·renderer·E2E 테스트가 추가된다.

## ADDED Requirements

### Requirement: 커밋별 변경 파일 탐색
시스템은 사용자가 그래프에서 커밋을 클릭하면 해당 커밋에서 변경된 파일 목록을 제공해야 한다(SHALL).

#### Scenario: 커밋 클릭
- **WHEN** 사용자가 커밋 하나를 클릭한다
- **THEN** 시스템은 해당 커밋의 추가, 수정, 삭제, 이름 변경과 바이너리 변경 파일을 목록으로 표시한다

#### Scenario: 다른 커밋으로 이동
- **WHEN** 사용자가 그래프에서 다른 커밋을 클릭한다
- **THEN** 시스템은 통합 대상 선택을 유지하면서 변경 파일 목록을 새 커밋 기준으로 갱신한다

#### Scenario: merge commit의 변경 파일 확인
- **WHEN** 사용자가 부모가 둘 이상인 merge commit을 클릭한다
- **THEN** 시스템은 비교할 부모를 선택할 수 있게 하고 현재 선택한 부모를 기준으로 변경 파일 목록을 표시한다

#### Scenario: 루트 커밋의 변경 파일 확인
- **WHEN** 사용자가 부모가 없는 루트 커밋을 클릭한다
- **THEN** 시스템은 빈 저장소 상태를 기준으로 추가된 파일 목록을 표시한다

#### Scenario: 커밋의 변경 파일 선택
- **WHEN** 사용자가 클릭한 커밋의 변경 파일 목록에서 파일을 선택한다
- **THEN** 시스템은 변경 파일 목록에 사용한 동일한 기준 상태와 해당 커밋 사이의 파일 변경을 표시하고 통합 대상 선택을 유지한다

### Requirement: 그룹별 변경 파일 탐색
시스템은 사용자가 통합 결과의 그룹을 펼쳐 포함된 변경 파일을 선택할 수 있게 해야 한다(SHALL).

#### Scenario: 그룹에서 파일 선택
- **WHEN** 사용자가 변경 그룹을 펼치고 파일을 선택한다
- **THEN** 시스템은 선택한 파일의 접근 가능한 전체 커밋 흐름과 통합 diff를 표시한다

### Requirement: 파일 전체 커밋 흐름
시스템은 저장소에서 접근 가능한 선택 파일의 전체 커밋 흐름을 제공하고 현재 통합 결과에 포함된 커밋을 강조해야 한다(SHALL).

#### Scenario: 파일을 여러 선택 커밋이 변경
- **WHEN** 선택한 파일이 여러 통합 대상 커밋에서 변경되었다
- **THEN** 시스템은 파일의 전체 커밋 흐름을 시간 순서로 표시하고 통합 결과에 기여한 커밋을 강조한다

#### Scenario: 파일 이름 변경
- **WHEN** 파일 경로가 커밋 흐름 중 변경되었다
- **THEN** 시스템은 이전 경로와 현재 경로를 하나의 파일 흐름으로 연결해 표시한다

#### Scenario: 파일 이력 일부 누락
- **WHEN** 저장소에 파일의 과거 이력 일부가 없다
- **THEN** 시스템은 확인 가능한 이력을 표시하고 누락 범위를 안내한다

### Requirement: 좌우 통합 diff
시스템은 기준 파일과 선택 커밋이 반영된 최종 파일을 좌우 비교 방식으로 표시해야 한다(SHALL).

#### Scenario: 수정 파일 비교
- **WHEN** 사용자가 수정된 파일의 통합 diff를 연다
- **THEN** 시스템은 기준 파일을 왼쪽에, 최종 파일을 오른쪽에 표시하고 대응하는 변경 구간을 정렬한다

#### Scenario: 여러 커밋이 만든 최종 변경
- **WHEN** 같은 파일에 여러 선택 커밋의 변경이 포함된다
- **THEN** 시스템은 커밋별 diff를 나열하지 않고 기준 파일과 최종 파일 사이의 하나의 좌우 diff를 표시한다

#### Scenario: 추가된 파일 비교
- **WHEN** 통합 결과에서 파일이 새로 추가된다
- **THEN** 시스템은 왼쪽을 빈 기준 상태로 표시하고 오른쪽에 추가된 파일 내용을 표시한다

#### Scenario: 삭제된 파일 비교
- **WHEN** 통합 결과에서 파일이 삭제된다
- **THEN** 시스템은 왼쪽에 삭제 전 내용을 표시하고 오른쪽을 빈 최종 상태로 표시한다

#### Scenario: 이름이 변경된 파일 비교
- **WHEN** 통합 결과에서 파일 이름이 변경된다
- **THEN** 시스템은 이전 경로와 현재 경로를 좌우에 표시하고 내용 변경을 함께 표시한다

#### Scenario: 바이너리 파일 비교
- **WHEN** 통합 결과에 바이너리 파일 변경이 포함된다
- **THEN** 시스템은 텍스트 diff를 표시하지 않고 이전 상태와 최종 상태의 파일 정보 및 변경 유형을 표시한다

### Requirement: 변경 맥락 유지
시스템은 사용자가 그래프, 커밋의 파일 목록, 그룹 트리와 diff 사이를 이동해도 현재 통합 선택과 탐색 맥락을 유지해야 한다(SHALL).

#### Scenario: 커밋 파일에서 통합 파일로 이동
- **WHEN** 사용자가 커밋의 변경 파일을 살펴본 뒤 그룹 트리의 파일을 선택한다
- **THEN** 시스템은 통합 대상 커밋 선택을 유지하고 선택한 파일의 통합 결과로 이동한다

### Requirement: 부분 결과 상태 표시
시스템은 문제 파일이 제외된 diff를 완전한 통합 결과와 구분해야 한다(MUST).

#### Scenario: 선택한 파일이 문제 파일임
- **WHEN** 사용자가 통합할 수 없는 파일을 선택한다
- **THEN** 시스템은 완성된 diff 대신 문제 원인과 확인 가능한 변경 정보를 표시한다

#### Scenario: 다른 파일은 정상임
- **WHEN** 일부 파일에만 문제가 있고 사용자가 정상 파일을 선택한다
- **THEN** 시스템은 정상 파일의 diff를 표시하면서 전체 결과가 부분 상태임을 계속 알린다

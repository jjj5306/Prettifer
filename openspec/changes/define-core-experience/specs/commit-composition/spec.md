## ADDED Requirements

### Requirement: 자유로운 커밋 선택
시스템은 그래프에 표시된 하나 이상의 커밋을 서로 인접하지 않아도 선택할 수 있게 해야 한다(SHALL).

#### Scenario: 비연속 커밋 선택
- **WHEN** 사용자가 커밋 a, b, c, d, e, f 중 b, d, f를 선택한다
- **THEN** 시스템은 b, d, f를 선택 상태로 표시하고 나머지 커밋을 결과 선택에서 제외한다

#### Scenario: 선택 가능성 우선
- **WHEN** 사용자가 관계가 복잡하거나 통합 가능 여부가 아직 확인되지 않은 커밋을 선택한다
- **THEN** 시스템은 선택을 받아들이고 통합 결과를 만드는 과정에서 지원 가능한 처리와 문제를 평가한다

### Requirement: 선택 상태와 탐색 상태 구분
시스템은 통합 결과에 포함할 커밋과 현재 내용을 살펴보는 커밋을 서로 다른 상태로 표시해야 한다(SHALL).

#### Scenario: 선택된 커밋과 클릭한 커밋이 다름
- **WHEN** 여러 커밋이 통합 대상으로 선택된 상태에서 사용자가 그중 하나를 클릭한다
- **THEN** 시스템은 통합 대상 표시를 유지하면서 현재 클릭한 커밋을 별도로 강조한다

### Requirement: 선택 커밋의 통합 결과
시스템은 선택한 커밋의 변경만 반영된 최종 결과를 하나의 통합 비교로 제공해야 한다(SHALL).

#### Scenario: 비연속 커밋의 최종 결과
- **WHEN** 사용자가 b, d, f를 선택하고 통합 결과를 요청한다
- **THEN** 시스템은 b, d, f의 변경을 Git 흐름에 맞는 순서로 반영하고 a, c, e의 변경을 제외한 최종 비교를 제공한다

#### Scenario: 같은 파일을 여러 커밋이 변경
- **WHEN** 여러 선택 커밋이 같은 파일을 변경한다
- **THEN** 시스템은 모든 선택 변경이 반영된 최종 파일과 기준 파일 사이의 하나의 통합 diff를 제공한다

### Requirement: 비교 기준 결정
시스템은 커밋 선택과 독립된 비교 기준을 사용하고, 실제로 사용한 기준을 표시해야 한다(SHALL).

#### Scenario: 비교 브랜치가 설정됨
- **WHEN** 현재 작업 브랜치에 비교할 기준 브랜치가 설정되어 있다
- **THEN** 시스템은 두 브랜치가 갈라진 지점을 기본 비교 기준으로 사용한다

#### Scenario: 커밋 선택 변경
- **WHEN** 사용자가 통합 대상 커밋을 추가하거나 해제한다
- **THEN** 시스템은 현재 비교 기준을 유지하고 선택된 변경만 다시 계산한다

#### Scenario: 비교 기준 변경
- **WHEN** 사용자가 다른 비교 기준을 선택한다
- **THEN** 시스템은 새 기준을 명확히 표시하고 현재 선택 커밋의 통합 결과를 다시 계산한다

#### Scenario: 루트 커밋 선택
- **WHEN** 비교 기준보다 앞선 상태가 없는 루트 이력을 검토한다
- **THEN** 시스템은 빈 저장소 상태를 비교 기준으로 사용한다

#### Scenario: 비교 기준을 결정할 수 없음
- **WHEN** 기준 브랜치가 없거나 누락된 Git 이력으로 기본 비교 기준을 하나로 결정할 수 없다
- **THEN** 시스템은 선택 상태를 유지하고 사용자가 비교 기준을 확인할 수 있게 후보와 필요한 이력을 안내한다

### Requirement: 적용 순서 결정
시스템은 조상 관계가 있는 선택 커밋을 Git 흐름 순서로 적용하고, 조상 관계만으로 순서를 정할 수 없는 커밋은 사용자가 순서를 확인한 뒤 적용해야 한다(SHALL).

#### Scenario: 조상 관계로 순서 결정
- **WHEN** 선택 커밋 사이의 조상 관계로 적용 순서를 결정할 수 있다
- **THEN** 시스템은 오래된 커밋부터 최신 커밋 순서로 적용한다

#### Scenario: 서로 다른 브랜치의 순서 확인
- **WHEN** 선택 커밋 사이에 직접적인 조상 관계가 없어 적용 순서가 하나로 결정되지 않는다
- **THEN** 시스템은 선택 상태를 유지하고 필요한 적용 순서를 사용자에게 확인한다

### Requirement: merge commit 기준 부모
시스템은 merge commit을 통합 결과에 포함할 때 변경 계산에 사용할 부모를 명확히 결정해야 한다(MUST).

#### Scenario: merge commit 선택
- **WHEN** 사용자가 부모가 둘 이상인 merge commit을 선택한다
- **THEN** 시스템은 기준 부모를 사용자에게 확인하고 선택된 부모를 통합 결과에 표시한다

### Requirement: 비교 기준과 포함 범위 표시
시스템은 통합 결과에 사용한 비교 기준과 포함된 커밋을 사용자가 확인할 수 있게 해야 한다(SHALL).

#### Scenario: 통합 결과 확인
- **WHEN** 통합 결과가 표시된다
- **THEN** 시스템은 비교 기준, 선택된 커밋 수, 포함된 커밋과 적용 순서를 함께 표시한다

### Requirement: 가능한 결과 우선 제공
시스템은 선택 조합에 문제가 있어도 내용 선택이 필요하지 않은 변경을 처리하고, 계산 가능한 파일의 검토용 결과를 최대한 제공해야 한다(SHALL).

#### Scenario: 일부 파일에서만 문제 발생
- **WHEN** 선택 커밋을 통합하는 과정에서 일부 파일만 계산할 수 없다
- **THEN** 시스템은 계산 가능한 파일의 결과를 계속 제공하고 문제 파일을 원래 그룹 위치에서 문제 상태로 표시한다
- **THEN** 시스템은 문제 요약에서 해당 파일의 원래 위치로 이동할 수 있게 한다
- **THEN** 시스템은 전체 상태를 실행 가능성이 검증되지 않은 부분 결과로 명확히 표시한다

#### Scenario: 시스템이 안전하게 처리할 수 있는 문제
- **WHEN** 통합 과정에서 경쟁하는 파일 내용 중 하나를 선택하지 않고 처리할 수 있다
- **THEN** 시스템은 선택을 중단시키지 않고 처리를 완료하며 처리 내역과 검증 범위를 표시한다

#### Scenario: 파일 내용 선택이 필요함
- **WHEN** 통합 과정에서 서로 다른 파일 내용 중 하나를 선택해야 한다
- **THEN** 시스템은 내용을 임의로 선택하지 않고 해당 파일을 문제 상태로 표시한다

### Requirement: 문제 상세 안내
시스템은 완전한 통합 결과를 만들 수 없는 문제를 커밋과 파일 단위로 설명하고 사용자가 다음 행동을 판단할 수 있게 해야 한다(SHALL).

#### Scenario: 파일 변경 통합 실패
- **WHEN** 특정 커밋의 변경을 특정 파일에 반영할 수 없다
- **THEN** 시스템은 문제 커밋, 문제 파일, 발생 원인과 필요한 다음 행동을 함께 표시한다

#### Scenario: 완전한 결과 없음
- **WHEN** 선택 조합 전체에 대해 신뢰할 수 있는 결과를 만들 수 없다
- **THEN** 시스템은 결과를 완료 상태로 표시하지 않고 확인 가능한 정보와 실패 범위를 제공한다

### Requirement: 현재 작업 상태 보호
시스템은 통합 결과를 계산하고 탐색하는 동안 사용자의 현재 Git 작업 상태를 변경하지 않아야 한다(MUST).

#### Scenario: 커밋되지 않은 작업이 존재함
- **WHEN** staged, unstaged 또는 untracked 변경이 있는 상태에서 사용자가 통합 결과를 요청한다
- **THEN** 시스템은 현재 브랜치와 작업 중인 변경을 그대로 유지한다

#### Scenario: 계산 취소 또는 실패
- **WHEN** 사용자가 계산을 취소하거나 계산이 실패한다
- **THEN** 시스템은 실행 전의 저장소 상태를 그대로 유지한다

### Requirement: 선택 변경에 따른 결과 갱신
시스템은 커밋 선택이 바뀌면 현재 선택에 맞는 통합 결과를 제공해야 한다(SHALL).

#### Scenario: 커밋 추가 또는 해제
- **WHEN** 사용자가 커밋을 추가로 선택하거나 기존 선택을 해제한다
- **THEN** 시스템은 새 선택 범위를 표시하고 통합 결과의 갱신 상태를 명확히 알린다

#### Scenario: 계산 중 선택 변경
- **WHEN** 통합 결과를 계산하는 동안 사용자가 커밋 선택을 변경한다
- **THEN** 시스템은 이전 계산 결과를 현재 선택의 결과로 표시하지 않고 새 선택 기준으로 갱신한다

### Requirement: 결과 일관성
시스템은 같은 저장소 상태, 비교 기준, 적용 순서와 커밋 선택에 대해 같은 통합 결과를 제공해야 한다(MUST).

#### Scenario: 동일 조건으로 다시 계산
- **WHEN** 저장소 상태, 비교 기준, 적용 순서와 선택 커밋이 바뀌지 않은 상태에서 결과를 다시 계산한다
- **THEN** 시스템은 이전 계산과 같은 파일 상태와 diff를 제공한다

### Requirement: 진행 상태와 취소
시스템은 통합 결과 계산의 진행 상태를 표시하고 사용자가 계산을 취소할 수 있게 해야 한다(SHALL).

#### Scenario: 계산 진행 중
- **WHEN** 통합 결과 계산이 1초 안에 끝나지 않는다
- **THEN** 시스템은 계산 중인 상태와 현재 처리 범위를 표시한다

#### Scenario: 계산 취소
- **WHEN** 사용자가 진행 중인 계산을 취소한다
- **THEN** 시스템은 계산을 중단하고 취소된 결과를 완료 상태로 표시하지 않는다

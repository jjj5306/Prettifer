## Context

Prettifer의 첫 제품 경험은 Git 그래프 탐색, 커밋 선택, 선택 결과의 통합 비교, 파일 그룹 탐색으로 이어진다. 현재 저장소에는 구현이 없으며, README의 초기 UX 목업이 화면 흐름을 보여준다.

이 설계는 코어가 보장할 사용자 동작을 구체화한다. 내부 결과 모델, 패키지 구조와 통합 결과 계산 기술은 구현 단계의 검증을 거쳐 결정한다.

## Goals / Non-Goals

**Goals:**

- 전체 Git 흐름을 탐색하면서 비연속 커밋을 자유롭게 선택한다.
- 선택한 커밋의 변경이 반영된 최종 결과를 하나의 좌우 diff로 제공한다.
- 선택 가능성을 넓게 유지하고 문제가 생기면 가능한 결과와 상세 안내를 함께 제공한다.
- 커밋 중심 탐색과 통합 결과 중심 탐색을 자연스럽게 연결한다.
- 경로와 확장자 규칙으로 변경 파일을 이해하기 쉬운 트리로 구성한다.
- 계산 과정에서 현재 작업 상태를 보호한다.

**Non-Goals:**

- 공개 API와 내부 결과 모델 확정
- CLI 명령과 출력 형식 확정
- 통합 결과 계산 기술 확정
- VS Code 세부 컴포넌트와 디자인 토큰 확정
- AI 요약, 자동 기능 분류, 계정, 결제와 원격 동기화

## Decisions

### 전체 Git 그래프를 탐색 시작점으로 사용

사용자는 현재 브랜치의 일부 구간에 제한되지 않고 저장소에서 접근 가능한 전체 흐름을 본다. 그래프는 분기와 병합 관계, 브랜치와 태그, 현재 위치를 함께 제공한다. 긴 히스토리는 탐색 위치를 유지하며 계속 불러온다.

### 통합 대상 선택과 현재 탐색 대상을 분리

체크 상태는 최종 결과에 포함할 커밋을 나타내고, 클릭 상태는 지금 상세 내용을 보는 커밋을 나타낸다. 사용자는 통합 대상 선택을 유지한 채 여러 커밋의 변경 파일을 비교할 수 있다. merge commit의 변경 파일은 사용자가 선택한 부모를 기준으로 표시하고, 루트 커밋은 빈 저장소 상태를 기준으로 표시한다.

### 선택을 먼저 허용하고 결과 생성 단계에서 문제를 평가

그래프에 표시된 커밋은 통합 가능성이 불확실해도 선택할 수 있다. 시스템은 결과 생성 시 내용 선택이 필요하지 않은 처리를 수행하고, 남은 문제를 커밋과 파일 단위로 표시한다. 선택 제한이 필요한 상태는 이유와 필요한 행동을 함께 제공한다.

### 비교 기준과 적용 순서를 명시

비교 기준은 커밋 선택과 독립적으로 유지한다. 현재 작업 브랜치에 비교할 기준 브랜치가 설정되어 있으면 두 브랜치가 갈라진 지점을 기본값으로 사용한다. 사용자는 기준을 확인하고 변경할 수 있으며, 기본값을 하나로 결정할 수 없으면 시스템이 후보와 필요한 이력을 안내한다. 루트 이력은 빈 저장소 상태를 기준으로 사용한다. 조상 관계가 있는 선택 커밋은 오래된 커밋부터 적용한다. 서로 다른 브랜치에 있어 조상 관계만으로 순서를 결정할 수 없는 커밋은 선택 상태를 유지한 채 사용자에게 적용 순서를 확인한다. merge commit은 변경 계산에 사용할 부모를 확인하고 결과에 표시한다.

### 완전 결과와 부분 결과를 구분

일부 파일에서 문제가 발생해도 계산 가능한 파일은 검토용으로 계속 탐색할 수 있다. 문제 파일은 기존 그룹 위치에서 문제 상태로 표시하고 문제 요약은 해당 위치를 참조한다. 부분 결과에는 저장소 전체의 실행 가능성이 검증되지 않았음을 지속적으로 표시한다.

### 최종 파일 상태를 좌우로 비교

파일 diff는 기준 파일을 왼쪽에, 선택 커밋이 반영된 최종 파일을 오른쪽에 둔다. 여러 커밋이 같은 파일을 변경해도 기준 파일과 최종 파일 사이의 통합 diff를 제공한다. 파일 위쪽에는 접근 가능한 전체 파일 이력과 통합에 포함된 커밋을 표시한다. 추가·삭제·이름 변경은 한쪽의 빈 상태와 경로 정보로 표현하고 바이너리 변경은 파일 정보와 변경 유형을 제공한다.

### 분류는 파일 경로와 확장자 규칙으로 구성

사용자는 기능과 문서 구조에 맞는 계층형 그룹을 만든다. 경로 규칙은 저장소 상대 경로와 `/` 구분자를 사용하며 `*`와 `**` 와일드카드를 지원한다. 확장자 규칙은 `.`으로 시작하는 확장자를 사용한다. 두 규칙은 대소문자를 구분한다. 여러 규칙이 일치하면 명시된 우선순위와 선언 순서로 주 그룹을 정한다. 설정이 없거나 일치하는 규칙이 없는 파일은 기본 그룹에 둔다. 잘못된 규칙은 위치와 원인을 안내하고 유효한 규칙은 계속 적용한다. 문제가 있는 파일도 원래 그룹 위치에서 유지한다.

### 저장소 상태 보호를 사용자 계약으로 정의

통합 결과 계산 방식과 관계없이 현재 브랜치, staged 변경, unstaged 변경과 untracked 파일은 유지한다. 작업 트리, 별도 Git 작업 공간 또는 다른 방식을 선택할 때 이 계약을 검증 기준으로 사용한다.

### 초기 목업을 화면 흐름의 기준으로 사용

`docs/assets/prettifer-initial-ux-mockup.png`는 커밋 그래프, 클릭한 커밋의 파일 목록, 그룹 트리, 파일 이력과 좌우 diff의 배치를 설명한다. 세부 시각 요소는 구현 과정에서 조정할 수 있다.

## Risks / Trade-offs

- [커밋은 적용되지만 기능 의존성이 누락될 수 있음] → Git에서 확인 가능한 문제와 실행 검증이 필요한 문제를 구분하고 결과에 검증 범위를 표시한다.
- [부분 결과가 완전한 결과로 오해될 수 있음] → 상단 상태, 그룹 트리와 파일 화면에 부분 결과 표시를 유지한다.
- [전체 그래프가 큰 저장소에서 느릴 수 있음] → 현재 탐색 구간을 우선 표시하고 이전 이력을 단계적으로 제공한다.
- [여러 브랜치의 커밋 순서가 모호할 수 있음] → 선택 상태를 유지하고 적용 순서를 사용자에게 확인한다.
- [파일 이름 변경으로 이력이 끊길 수 있음] → 이전 경로와 현재 경로를 연결해 하나의 파일 흐름으로 표현한다.
- [문제 자동 처리가 결과 의미를 바꿀 수 있음] → 경쟁하는 파일 내용 중 하나를 선택하는 처리는 자동으로 수행하지 않는다.

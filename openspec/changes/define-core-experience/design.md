## Context

현재 구현은 사용자가 선택한 두 브랜치의 공통 조상부터 작업 브랜치까지 이어지는
선형 커밋 흐름을 제공한다. 사용자는 이 범위에서 커밋을 선택하고 통합 결과의
추가, 수정, 삭제 및 바이너리 파일을 검토할 수 있다.

이 설계는 전체 저장소 흐름, 불완전한 이력, 루트 이력, 이름 변경 파일과
장시간 계산 검증에 필요한 동작을 정의한다.

## Goals / Non-Goals

**Goals:**

- 분기와 병합 관계를 포함한 전체 커밋 흐름을 그래프로 제공한다.
- 그래프의 커밋에 연결된 브랜치와 태그를 표시한다.
- 저장소 이력이 일부만 있어도 확인 가능한 범위와 원인을 제공한다.
- 루트 이력은 빈 저장소 상태를 기준으로 결과를 계산한다.
- 이름 변경 파일의 이전 경로, 현재 경로와 내용 변경을 함께 표시한다.
- 원본 기능 시나리오의 자동 검증 연결과 장시간 계산의 처리 범위 및 취소를
  확인한다.

**Non-Goals:**

- 공개 API와 명령줄 사용 방식 확정
- 데스크톱 화면 구성과 시각 요소 변경
- 설치 패키지와 공개 배포 방식 변경

## Decisions

### 전체 저장소 흐름을 그래프로 제공

그래프는 저장소에서 확인할 수 있는 커밋의 분기와 병합 관계를 표시한다. 각
커밋에는 연결된 브랜치와 태그를 함께 표시해 사용자가 흐름 안에서 현재 위치와
주요 지점을 식별할 수 있게 한다.

### 불완전한 이력의 확인 범위를 표시

얕은 복제 또는 누락된 Git 자료로 전체 흐름을 만들 수 없으면 현재 확인 가능한
커밋을 계속 표시한다. 화면에는 확인 가능한 범위, 누락된 범위와 원인을 함께
제공한다.

### 루트 이력은 빈 저장소 상태를 기준으로 계산

이전 커밋이 없는 루트 이력을 검토할 때는 파일이 없는 저장소 상태를 비교
기준으로 사용한다. 루트 커밋에서 생긴 파일은 모두 새 파일로 계산한다.

### 이름 변경 파일의 두 경로를 보존

최종 결과에서 이름이 변경된 파일은 이전 경로를 왼쪽에, 현재 경로를 오른쪽에
표시한다. 내용도 변경되었으면 두 경로의 파일 내용을 같은 좌우 비교에서
제공한다.

### 남은 시나리오를 실제 흐름에서 검증

각 요구사항을 자동 검증 항목에 연결한다. 계산이 1초를 넘으면 현재 처리 범위를
표시하고, 사용자가 취소하면 진행 중인 작업을 중단하며 완료 결과로 표시하지
않는지 확인한다.

## Risks / Trade-offs

- [전체 커밋 흐름 조회가 오래 걸릴 수 있음] → 확인된 구간부터 표시하고 남은
  구간의 조회 상태를 안내한다.
- [일부 이력이 전체 이력으로 보일 수 있음] → 확인 가능한 범위와 누락 원인을
  그래프와 함께 표시한다.
- [루트 이력의 파일이 결과에서 빠질 수 있음] → 빈 저장소 상태와 루트 커밋을
  비교하는 검증 저장소를 사용한다.
- [이름 변경이 파일 삭제와 추가로 분리될 수 있음] → 이전 경로와 현재 경로를
  하나의 변경으로 검증한다.
- [장시간 계산의 현재 상태를 판단하기 어려울 수 있음] → 처리 범위와 취소
  상태를 화면과 자동 검증에서 확인한다.

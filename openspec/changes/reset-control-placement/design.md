## Context

Commit History는 높이가 고정된 가로 바다. 준비된 상태의 패널은 `제목 줄 / 커밋 목록 / 더
불러오기` 세 칸 그리드이고, 목록은 세로 넘침을 잘라낸다. #87 에서 초기화 두 개를 더할 때 선택
초기화는 제목 줄 안에, 불러온 커밋 초기화는 세 칸 뒤에 놓였다. 뒤에 놓인 쪽은 그리드에 네 번째
칸을 만들어 `Load 100 older commits` 오른쪽에 따로 선다.

되돌리기의 동작 자체는 #87 에서 정해졌고 이번 change는 그것을 다시 정하지 않는다.

## Goals / Non-Goals

Goals

- 두 초기화가 한 자리에 묶여 보인다
- 아이콘만 보이는 상태에서도 무엇을 되돌리는지 알 수 있다
- 커밋 카드가 쓸 수 있는 폭이 줄지 않는다

Non-Goals

- 무엇이 초기화되는지 바꾸는 것
- 다른 패널의 버튼 배치
- 앱 전체에 쓸 tooltip 컴포넌트를 만드는 것

## Decisions

### 두 초기화를 제목 줄의 동작 묶음에 모은다

패널이 이미 가진 세 칸 뒤에 컨트롤을 더하면 칸이 하나씩 늘어난다. 초기화가 늘어날 때마다 바의
가로 배분이 바뀌는 구조라 자리가 정해져 있지 않은 것과 같다.

제목 줄은 이미 `Commit History`와 `N selected`를 담고 있고 커밋 목록과 별개 칸이다. 여기에
오른쪽 정렬 동작 묶음을 하나 두면 초기화가 몇 개든 그 안에서 늘어난다. 패널 제목 줄에 그 패널의
동작을 모으는 것은 VS Code 패널이 쓰는 배치이기도 하다.

`Load 100 older commits`는 옮기지 않는다. 그것은 되돌리기가 아니라 목록을 늘리는 주 동작이고,
목록 옆에 있어야 무엇을 늘리는지 읽힌다.

### 라벨을 아이콘으로 바꾸고 설명은 호버에서 보여준다

`Clear selection`과 `Reset loaded commits`는 합쳐서 30자가 넘는다. 고정 높이 바에서 그만큼은
커밋 제목이 잘리는 폭이다.

아이콘만으로는 두 초기화가 구별되지 않으므로 설명이 있어야 한다. 설명에는 무엇을 되돌리는지와
무엇을 남기는지를 함께 적는다. 두 초기화가 서로를 건드리지 않는다는 것이 이 기능의 핵심이고,
그것을 알 수 있는 자리가 여기뿐이다.

### 설명은 브라우저 기본 tooltip을 쓴다

activity rail의 아이콘 버튼이 이미 같은 방식이다. `title`로 설명을 주고 `aria-label`로 이름을
준다. 같은 앱에서 같은 모양의 컨트롤이 다른 방식으로 설명을 띄우면 그 차이 자체가 규칙처럼
읽힌다.

직접 만든 tooltip은 위치 계산, 포인터가 아닌 입력, 화면 밖으로 나가는 경우와 사라지는 시점까지
떠안는다. 이 change가 다루는 것은 버튼 두 개의 자리다.

`aria-label`이 이름을, `title`이 설명을 맡는다. 이름이 따로 있으면 `title`은 접근성 설명으로
읽히므로, 화면 낭독기를 쓰는 사용자는 이름과 설명을 함께 듣는다. 이름을 설명 문장으로 대신하면
목록에서 컨트롤을 부를 짧은 이름이 없어진다.

남는 것은 낭독기 없이 키보드만 쓰는 경우다. 기본 tooltip은 포인터 호버에서만 보인다. 보이는
설명을 초점에서도 띄우는 것은 activity rail을 포함해 앱 전체에서 같이 다룰 일이다.

### 되돌릴 것이 없으면 감추는 규칙을 유지한다

#87 의 결정을 그대로 둔다. 동작 묶음이 비면 묶음 자체가 자리를 차지하지 않는다.

## Risks / Trade-offs

- 아이콘은 라벨보다 뜻이 덜 분명하다. 처음 보는 사용자는 호버해야 알 수 있다. 되돌리기는 주
  동작이 아니라 필요할 때 찾는 동작이므로 이 비용을 받는다
- 포인터 없이 쓰는 사용자에게 보이는 설명이 없다. 접근성 이름으로 메우고, 보이는 설명은 앱 전체
  과제로 남긴다

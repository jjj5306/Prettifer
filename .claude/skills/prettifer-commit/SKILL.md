# Prettifer Commit

현재 이슈에 포함된 변경만 검증하고 프로젝트 커밋 컨벤션으로 커밋한다.

## Workflow

1. 사용자가 커밋 메시지 초안, 스테이징과 커밋 중 어떤 작업을 요청했는지 확인한다.
2. 저장소 루트의 `AGENTS.md`와 `.github/COMMIT_TEMPLATE.md`를 읽는다.
3. 현재 브랜치에서 이슈 번호를 확인한다. 확인할 수 없으면 연결된 GitHub 이슈를 확인한다.
4. `git status --short --branch`, `git diff`, `git diff --cached`로 변경 범위를 확인한다.
5. 현재 이슈와 관련 없는 변경을 스테이징하지 않는다.
6. OpenSpec change가 있으면 상태와 검증 결과를 확인한다.
7. 문서 검사, 테스트, lint, build 중 현재 변경에 필요한 검증을 실행한다.
8. 검증이 실패하면 커밋하지 않고 원인과 영향을 보고한다.
9. 커밋 메시지 초안만 요청받은 경우 아래 형식의 초안을 보고하고 저장소를 변경하지 않는다.
10. 스테이징 또는 커밋을 요청받은 경우 의도한 파일만 명시적으로 스테이징하고 스테이징된 diff를 다시 확인한다.
11. 스테이징만 요청받은 경우 스테이징된 파일과 검증 결과를 보고하고 커밋하지 않는다.
12. 커밋을 요청받은 경우 아래 형식으로 커밋하고 커밋 ID를 보고한다.

## Commit Message

```text
<type>: #<issue-number> <summary>

- <detail>
```

- `type`은 `feat`, `bug`, `docs`, `test`, `refactor`, `style`, `perf`, `build`, `ci`, `chore` 중에서 선택한다.
- 상세 내용은 복잡한 변경이나 추가 설명이 필요한 경우에만 작성한다.
- 상세 내용에는 변경 사항과 필요한 이유를 항목별로 작성한다.
- 제목 끝에 마침표를 사용하지 않는다.

## Stop Conditions

- 이슈 번호를 확인할 수 없음
- 현재 이슈 변경과 다른 변경을 안전하게 구분할 수 없음
- 커밋하려는 스테이징 범위에 현재 이슈와 관련 없는 내용이 포함됨
- 필수 검증 실패
- 스테이징 또는 커밋을 요청했지만 현재 이슈에 해당하는 변경이 없음

중단 조건이 있으면 커밋을 생성하지 않고 필요한 조치를 보고한다.

## Output

- 메시지 초안: 제안한 커밋 메시지와 판단한 이슈 번호
- 스테이징: 스테이징한 파일, 제외한 변경과 검증 결과
- 커밋: 커밋 ID, 최종 커밋 메시지와 검증 결과
